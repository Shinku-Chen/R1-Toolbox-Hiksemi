# R1 Toolbox 部署说明

## 常驻部署与默认服务

仓库 [composer.yml](../../composer.yml) 是通用 demo；[composer.dev.yml](../../composer.dev.yml) 是完整开发者示例，默认使用 `preview`、1440 分钟初始化窗口及受限命令诊断，必须填写 `R1_DEV_ALLOW_IPS` 的局域网 IP／CIDR。两份配置复用相同容器和数据卷，选择一份更新原项目即可。若已从网页保存“服务与开发”，开发开关、白名单及到期时间应在网页修改，环境变量不覆盖保存值。

1. 从 Actions 下载成功构建的部署文件，或使用提供的 `composer.yml`。
2. 在 NAS Docker 市场更新原项目配置或创建项目，然后启动。
3. 默认 `UI_MODE: image`、`UI_DIR: ''`：无需上传任何 HTML 或前端目录。
4. 观察日志：镜像包校验、RAM 目录展开和 Web 常驻服务启动后，容器应持续显示“运行中”。小屏默认开启；图形环境缺失或切换失败会单独显示原因，Web 继续运行。

离线部署先在镜像页面导入同包的 `r1-toolbox-linux-amd64.tar`。Compose 与离线包的镜像标签必须一致。

小屏接管仍需已有可运行的 `/screen/squashfs-root/AppRun`，不自动解包官方 AppImage；这个条件不再阻止 Web 核心启动。新版环境变量示例：

```yaml
environment:
  UI_MODE: image
```

默认 `UI_MODE=image`。`container_name` 默认 `r1-toolbox`；如需改名，同时设置 `TASK_CONTAINER` 为相同名称。Web 默认 `0.0.0.0:18732`，常驻模式不接受端口 `0`；可改为其他有效端口，或用 `R1_WEB_BIND: '127.0.0.1'` 限制本机访问。

内置界面保留概览、存储、网络、应用、温度、设置六个入口，通过卡片进入详情。真实数据由常驻 Python 核心持续采集；关闭小屏不停止监控、网页、灯光或风扇服务，停止容器则停止整套运行时并执行恢复。未知温度、首次差分和读取失败显示 `--` 或采集中，不填模拟数据。完整范围见[功能与支持条件](../../docs/features.md)。

当前固件没有 IT87 hwmon/PWM，但原厂路径不能仅据此否定。同一固件有不同的 rootfs/initrd hikio，前者缺调速、后者实现；两者都缺旧 RPM 查询。用户已读取实际加载模块 GNU note，确认与 initrd 支持版完全一致，原厂 Unix GET 也已返回 b'5'/auto，可在条件满足时开放系统风扇策略；物理效果仍需观察。未知/旧版模块仅只读，文件或 socket 存在不会自动解锁。对照值与识别步骤见 [官方接口审查](../../docs/histor-interfaces.md)。不加载/替换内核模块，不使用 /dev/port。

Compose 中的 `r1-toolbox-data:/data` 是独立命名卷，保存面板、亮度、风扇／灯光规则、历史与统计，以及 `web/service-settings.json` 服务偏好和 `web/api-access.json` Token 摘要。风扇规则的待用配置与最后成功应用配置分别保存。网页和小屏读取同一服务状态，不依赖浏览器存储。宿主核心通过 Docker `.Mounts.Source` 解析卷位置，但其前台生命周期与容器一致。不要把 `/data` 改为官方小屏目录；缺少可写卷时拒绝启动。

更新镜像、Docker/NAS 重启、删除并重新创建容器不会删除命名卷。请更新原项目并复用原卷；卷的实际名字通常带 Docker 项目前缀。删除项目时保留该卷，并不要执行清理卷或删除卷的操作，就能留住设置。若以不同项目名重建，需要显式复用旧卷，不能把新建的空卷误认为旧配置丢失。

## 网页配置

浏览器访问 `http://NAS_IP:18732`。默认 `password` 模式首次没有口令，监控与管理直接可用；可在“设置 → 登录口令”添加并开启，之后访问网页需要登录。显式 `R1_WEB_AUTH_MODE: pair` 才使用旧五位配对流程，180 秒有效、一次使用、会话最长 8 小时。两种模式均保留同源／JSON／CSRF 校验。公开结构化 API 为 `/api/v1/status`，历史、流量、告警、报告、CSV 和 OpenAPI 见[接口说明](../../docs/public-api.md)。

网页可设置亮度、屏保、息屏、灯光、独立风扇和历史统计。CPU／系统风扇提供自动、高、中、低、手动曲线，保存按现有校验流程应用；真实接管状态、触发来源和请求输出独立显示，不能用保存成功代替机械效果。待用与成功应用规则仍分开保存。见[独立温控指南](../../docs/fan-policy.md)。

“设置 → 服务与开发”分别管理小屏、MCP 与开发模式。小屏默认开，关闭会恢复官方窗口；勾选状态是保存意图，需同时查看实际 `active/busy/last_error`。MCP 默认关，关闭后密钥保留。开发模式默认关，开启必须有非空局域网 IP／CIDR 白名单和 1～1440 分钟时限，Web 保存的绝对到期时间跨重启保留，不会自动续期。Token 由“API 管理”创建、编辑、停用、轮换或撤销，独立于开发白名单；见[MCP 说明](../../docs/mcp-api.md)与[开发诊断](../../docs/dev-diagnostics.md)。

网页和监控由容器前台监督，Web 端口被其他服务占用时核心启动失败并报告原因，不能以空闲容器伪装正常，也不会结束无关占用程序。当前为局域网 IPv4 HTTP；服务地址只广告实际 IPv4 监听，网络详情提供 IPv6 信息不代表监听 IPv6。

## UI 模式

| UI_MODE | 用途 | UI_DIR |
|---|---|---|
| image | 使用镜像内置 UI，默认部署方式 | 必须为空 |
| diagnostic | 启动 Web 核心，不提供小屏接管前端 | 保持为空 |
| directory | 只读挂载用户在 NAS 数据盘上的完整前端目录 | NAS 宿主绝对路径 |

常驻入口未设置 `UI_MODE` 时默认 image；自有目录必须显式选择 directory。旧 `NEW_HTML` 复制参数已停用，请移除。

每次容器启动均校验包并启动常驻核心；不按旧 `/run/r1-toolbox/last-success` 标记跳过运行。服务偏好保存后优先于环境初始值；`R1_SMALL_SCREEN_ENABLED=0` 仅用于尚无持久设置时默认关闭小屏。

## 镜像如何提供 UI

构建时将 `ui/` 和原创 Python 监控/控制服务打包进镜像。容器启动后通过宿主 `docker cp` 读取内置包，先确认 `/run` 及其运行目录确实位于 tmpfs，再验证 SHA256、文件清单、路径、类型与大小限制。在随机暂存目录中校验完成后，原子发布到 `/run/r1-toolbox/ui-<内容摘要>`；复用缓存也重新校验。

容器前台经 `nsenter` 在宿主命名空间运行 `ui_service.py --resident`，不脱离容器后台保活。小屏独立临时服务将缓存的 `frontend` 用 `BindReadOnlyPaths` 只读挂载到 `/screen/squashfs-root/resources/app/dist`；挂载仅影响窗口服务视图，宿主原目录保持原样。Web／监控核心和 `AppRun` 生命周期分离，关闭或崩溃的小屏不会结束 Web。设置写入数据卷，不写只读前端。

仅复制、展开到 `/run` 运行目录，不覆盖原版 AppImage、解包版前端或 `/screen/screen-app-startup.sh`。不绑定 Docker 内部镜像层路径，也不要求新版 Compose 的 image volume 语法。

启动前识别 Electron 主进程及其 Chromium 子进程，兼容子进程将命令行改写为一段进程标题的情况。必须只有一个主进程，且所有小屏子进程属于它；多个实例或归属不明时保留现有程序并输出进程诊断。

停原程序前会先用同样的只读绑定属性启动检查服务，确认挂载身份与只读状态。新小屏主进程还需在独立 cgroup 以同一个 PID 和启动时间连续存活 3 秒，并通过自己的 `/proc/PID/root` 文件视图验证挂载。失败时尽力停止新服务，无自定义挂载地恢复原解包程序。

HistorSub 1.1.15 默认创建隐藏窗口。内置 UI 通过官方 `showWin` 显示握手启动窗口定位，收到官方在显示后发出的 `sendAppPath` 回执，再发送 `deviceStatus` 结束定位轮询。普通浏览器预览不发送 Electron 消息；握手脚本独立于状态采集和页面交互加载。容器的进程、挂载检查通过后，仍需确认实机画面与触摸。

## 实时指标与控制

Python 标准库采集 `/proc`、sysfs 与真实数据盘挂载点，基础指标约每 2 秒更新；可选命令在后台分开执行：

- CPU 使用率、可用的 CPU 温度、内存占用、运行时长。
- 默认路由网卡的 IPv4、上下行速率，避免累计 Docker 网桥。
- `/drives/` 下数据盘容量，按文件系统去重。
- CPU 分核、负载、Swap、进程、监听端口、多网卡 IPv4/IPv6、链路速率/双工/MTU 与可用的 GPU sysfs 信息。
- OS/内核/允许列表内的固件版本、DMI、CPU 拓扑/频率、PCI、通用风扇转速、各温度测点、mdraid 状态等设备详情；独立后台低频采集，单项失败不阻塞基础指标。序列号与 MAC 仅在本机展示，不外发。
- 物理磁盘型号、容量、温度与 SMART；使用 `smartctl -n standby -j -a`，结果缓存 30 秒，休眠或不支持时如实显示不可用。
- Docker 容器状态和资源统计；有 `virsh` 且 libvirt 可访问时读取虚拟机状态。

CPU/内存趋势只保留内存中最近 120 次采样，服务退出后清空。设备详情默认约每 30 秒刷新。数据为空、缺工具、接口失效或权限不足时返回原因；独立详细采样失败不会阻塞基础 CPU/网口刷新。没有实际来源的模块隐藏，系统→设备能力仍可查看原因。GPU 利用率和显存字段只在宿主实际提供时显示，不保证当前 Intel GPU 有利用率读数。

本机 API 监听 `127.0.0.1:18731`。`GET /api/status`、`GET /api/toolbox`、`GET /api/insights`、`GET /api/fan-policy` 为读取接口；`POST /api/action` 需要 JSON、允许的 Host／Origin 与 `X-R1-Token`。令牌每次核心启动随机生成，只传给本次小屏 Electron 环境，不写入前端或读取接口。普通浏览器预览只有读取能力。网页使用独立的可选口令／显式配对授权与 CSRF，MCP 使用独立 API Token，不暴露本机小屏令牌。

控制页根据实际能力开放操作：

- 亮度、立即息屏/唤醒、无操作息屏和夜间低亮度；息屏后的第一次触摸仅唤醒，避免误触底下的按钮。实机可能出现原始 `brightness=0` 但画面正常，因此不单凭该值判定息屏。
- CPU／系统独立温控：网页分别选模式、来源与规则；每路 Ts<Tn<Tf、阈值 15–85°C，静音／普通输出 10–100% 且非降，全速固定 100%，最低 raw26，拒绝更低或零输出。输出是控制请求，不是实测 RPM。升温下一轮升档；全速降档低于 Tf−3°C，普通回静音到 Ts。所选必要来源缺失或过期，本路保护全速；即使手动或只选硬盘也持续检查 CPU 保护。温度参考取原始 °C 最大值，CPU 与硬盘正常范围不同，混选可能由 CPU 主导。
- 控温来源由独立目录读取：CPU／主板 sysfs 每秒更新、最多允许 3 秒旧值；SMART 复用不唤醒休眠盘的低频结果，通常约 30 秒更新、最多 90 秒。刷新网页不刷新旧温度的采样时间，明确且新鲜的休眠盘可排除，不能把失联当休眠。
- 独立接管还需白名单温控二进制、实际加载驱动、唯一原厂进程、字符设备和 Linux amd64 RAM 适配层。确认应用后，独立 systemd 监督服务重启同一 `temp_control` 加载窄适配层，只处理被选风扇请求，未选通道及硬盘请求透传。硬盘休眠线程继续存在，交接会重建计时；不修改官方文件、持久改写 `fan_mode` 或重启 `emhistor`。物理对应及机械调速效果尚未实机验证，目标百分比不是 RPM。
- 原厂系统风扇低／中／高／自动策略仍是另一条路径，仅影响 `0x5799`，CPU 原厂线程独立每 10 秒写 `0x5798`。原厂策略只对白名单 loaded GNU note 开放、每次操作重验；未知／旧版只读。普通后台探测不发有副作用的 GET/SET/信号，独立接管流程则按授权同步既有模式。独立运行、切换或恢复未确认时不能混用原厂／其他 PWM 控制；模式1停扇不提供，旧 RPM 仍显示未知。
- 受支持的 IT87 hwmon/PWM 通道另提供显式接管：手动 50–100% 占空比，低/中/高 60/80/100%，软件自动或 2–8 点自定义曲线。曲线温度 20–90℃递增、占空比 50–100% 非降；缺 CPU 温度或 ≥80℃请求满速。同号 RPM 为 0 请求满速并显示原因；编号与实际物理风扇的对应仍需确认。当前用户固件未发现这些通道。原厂系统风扇策略与 hwmon 曲线是两条不同路径。
- RGB按原厂DesignWare适配器名称自动识别，只读验证固定0x26地址与0x01=0x55身份，唯一候选才开放，不需手选总线、不带-f。模式0x90、亮度0x91、RGB 0x92／93／94，写后读回。支持最高温颜色渐变及跨午夜夜间亮度上限，默认仅探测，用户应用的持久规则才启用；外部改灯让回。见[灯光说明](../../docs/light-policy.md)。
- Docker 仅启动/停止/重启，保护 Toolbox 自身；VM 仅 start/shutdown/reboot/suspend/resume，不提供删除或强制断电。
- NAS 重启/关机需确认，5 秒内可取消，之后交由固定的 `systemctl` 操作执行。没有 RTC、WOL 或关机后自动开机功能。

面板、独立风扇、灯光及统计设置保存到同一独立数据卷。风扇／灯光待用与成功应用规则分离，保存不改变当前控制；成功应用才启用恢复，故障／竞争后停用恢复。历史最长30日、每30秒批写，可关闭；可能增加数据卷所在盘的I/O。IT87临时接管与待执行电源请求不跨启动恢复。

关闭可选小屏只恢复官方窗口，核心风扇／灯光策略继续运行。正常停止容器／核心时取消电源请求，并尽力恢复官方窗口、hwmon PWM／enable、背光／blank和灯光。独立风扇监督服务仍处理进程退出、5 秒租约失效、身份变化和写入失败，先请求安全输出再恢复原厂执行者及既有策略。恢复未确认必须保留错误，不能只按 vendor／active=false 判断成功。旧即时 RGB 设置与另行确认的原厂系统风扇策略不因恢复 UI 自动撤销。突然断电或硬件异常仍不能保证恢复成功。

核心与小屏独立：窗口退出会尝试恢复官方显示并留下诊断，Web 继续运行；核心退出则容器退出并按 Docker 重启策略处理。本机状态端口或必需的 Web 端口被占用时明确失败，不覆盖或结束无关程序。

## 常驻、升级与恢复

保留 `restart: always`。容器前台监督真实宿主核心，不再在任务完成后自行停止；核心异常退出交由 Docker 重启。收到正常停止信号后等待恢复与清理，不用 `sleep infinity` 维持表面运行。宿主单实例锁防止同一时间启动两套核心。

只恢复官方界面：在“服务与开发”关闭 Toolbox 小屏，核对实际状态。停止整套 Toolbox：正常停止原容器，清理流程尝试恢复官方显示和风扇；需要恢复开机原行为时删除部署并正常重启 NAS。官方启动流程继续使用未改写的原文件。

删除项目可保留独立数据卷；删除卷会丢失Toolbox面板、风扇、灯光、统计设置和历史。实际卷名可能带项目前缀；恢复官方UI不需要删除该卷。

从旧自停止版本升级时，启动流程只迁移经名称、命令与绑定来源确认的旧 Toolbox 服务，不能因端口或服务名相近就停其他程序。旧版若曾覆盖过 HTML，仍需另外恢复当时的备份；内存挂载不会回退历史文件修改。

## 自定义目录模式

将自有界面放在数据盘，例如 `/drives/实际磁盘/R1-Toolbox/ui`，包含 `index.html` 及其引用的 JS、CSS、图片。然后设置：

```yaml
UI_MODE: directory
UI_DIR: /drives/实际磁盘/R1-Toolbox/ui
```

这是宿主路径，不是 `/host/...`。无需额外添加 Docker volume，已有宿主访问入口会让小屏服务建立私有挂载。目录会遮住窗口视图中的整个原版 `dist`，必须提供完整资源。directory 模式仍使用镜像里的常驻 Web／监控核心，自定义页面是否读取这些 API 由页面自身决定。

目录路径支持普通中文，不支持空白、冒号、反斜杠、引号、`%`、`$`、控制字符。源目录不能与目标相同或互为祖先；原子更名整个源目录后需要重跑挂载。

## 依赖、日志与边界

- 宿主核心需要 `docker`、支持 `--cgroup`／`--no-fork` 的 `nsenter`、`mountpoint`、`sha256sum`、`python3`。小屏实际挂载另需 systemd 233 起的 `BindReadOnlyPaths`、`systemd-run`、`systemctl` 和现有图形环境；缺图形环境不阻止 Web 启动。
- 容器名与 `TASK_CONTAINER` 保持 `r1-toolbox`。镜像继承 `docker.io/library/debian:bookworm-slim`，保留原宿主访问机制，不联网安装宿主工具。
- 镜像模式要求 `/run` 为 tmpfs；不满足时在停原小屏前拒绝部署 UI。缺少依赖或包损坏也不会停止原程序。
- 核心日志直接出现在容器日志，小屏临时服务名为 `r1-toolbox-screen-<PID>.service`，恢复官方窗口另有对应服务。失败暂存保留至重启，便于排查。
- 执行状态、UI 和采样历史位于运行时目录；Toolbox 设置写入独立数据卷，Electron、系统、Docker 仍可能写正常配置、缓存和日志，不能保证整机零写入。
- 未提供联网天气、SMTP／Server酱、外部iDRAC、fnOS相册／影视／音乐统计、本地播放器、飞牛音乐代理、视频壁纸／主题编辑器、每天固定时刻亮熄屏、HTML报告和容器每日／月累计。现有JSON报告、CSV、SQLite历史、网卡日／月流量、SMART健康观测与灯光温度／夜间联动不代替这些缺失模块。见[功能矩阵](../../docs/features.md)和[需求核对](../../docs/requirements-audit.md)。
- 真实 NAS 的画面、触摸、开机时序及厂商守护程序行为需要实机验证；本版独立接管仅有模拟温度／进程、内存适配器和 Linux ioctl 替身验证，尚未确认用户设备的机械风速与物理通道对应。
