# R1 Toolbox 部署说明

## 直接使用镜像内置 UI

1. 从 Actions 下载成功构建的部署文件，或使用提供的 `composer.yml`。
2. 在 NAS Docker 市场更新原项目配置或创建项目，然后启动。
3. 默认 `UI_MODE: image`、`UI_DIR: ''`：无需上传任何 HTML 或前端目录。
4. 观察日志：镜像 UI 包校验、RAM 目录展开、只读挂载预检、小屏启动验证通过后，容器应显示“已停止”。

离线部署先在镜像页面导入同包的 `r1-toolbox-linux-amd64.tar`。Compose 与离线包的镜像标签必须一致。

当前仍需已有可运行的 `/screen/squashfs-root/AppRun`，不自动解包官方 AppImage。新版环境变量示例：

```yaml
environment:
  TASK_CONTAINER: r1-toolbox
  TASK_REVISION: '6'
  UI_MODE: image
  UI_DIR: ''
  R1_WEB_BIND: '0.0.0.0'
  R1_WEB_PORT: '18732'
```

内置界面保留概览、存储、网络、控制、应用、系统、设置七个入口，通过大卡片/列表进入二级、三级详情，返回按钮随时可用。主页面可左右滑动，详情内容独立滚动，避免在小屏堆满指标与开关。真实数据通过随小屏运行的 Python 服务持续采集，Toolbox 容器结束不影响刷新。未知温度、首次差分和读取失败会显示 `--` 或采集中，不填模拟数据。完整范围见 [功能与支持条件](../../docs/features.md)。

当前固件没有 IT87 hwmon/PWM，但原厂路径不能仅据此否定。同一固件有不同的 rootfs/initrd hikio，前者缺调速、后者实现；两者都缺旧 RPM 查询。用户已读取实际加载模块 GNU note，确认与 initrd 支持版完全一致，原厂 Unix GET 也已返回 b'5'/auto，可在条件满足时开放系统风扇策略；物理效果仍需观察。未知/旧版模块仅只读，文件或 socket 存在不会自动解锁。对照值与识别步骤见 [官方接口审查](../../docs/histor-interfaces.md)。不加载/替换内核模块，不使用 /dev/port。

Compose 中的 `r1-toolbox-data:/data` 是独立命名卷，保存主题、字号、页面、轮播、息屏和亮度等设置。网页和小屏写入同一个 `settings.json`，不依赖浏览器存储；保存完成后刷新/重新配对会从服务读回。宿主服务通过 Docker `.Mounts.Source` 解析卷的位置，不依赖容器继续运行。不要把 `/data` 改为官方小屏目录。新版 image 模式缺少可写卷时会在停止原小屏前拒绝部署，避免把设置只存在内存中。

更新镜像、Docker/NAS 重启、删除并重新创建容器不会删除命名卷。请更新原项目并复用原卷；卷的实际名字通常带 Docker 项目前缀。删除项目时保留该卷，并不要执行清理卷或删除卷的操作，就能留住设置。若以不同项目名重建，需要显式复用旧卷，不能把新建的空卷误认为旧配置丢失。

## 网页配置

使用浏览器访问 `http://NAS_IP:18732`，在小屏“设置 → 网页配置”点击生成配对码，再在网页输入。配对码为 10 位数字、180 秒有效且一次使用；重新生成后旧码失效。网页登录与小屏不共享私有控制令牌。会话最多 8 小时，重启服务后失效，但数据卷中的配置保持不变。

网页可以设置主题、字号、启用页面、轮播、空闲息屏、亮度与夜间调暗；可用的屏幕和已经在本机验证的灯光还可即时操作。RGB 即时操作不作为开机配置自动恢复。CPU 独立温控仍未接管，不在网页提供无效开关。小屏继续提供常用状态与快捷操作。

网页由 `/run` 中的宿主临时服务运行，部署容器执行后仍会停止，不需要容器常驻。网页端口被其他服务占用时，只禁用网页并显示原因，小屏继续运行，不结束占用端口的程序。当前为局域网 IPv4 HTTP；服务地址列表只广告实际监听的 IPv4 地址，IPv6 信息在网络详情中查看。`R1_WEB_PORT: '0'` 关闭网页，或 `R1_WEB_BIND: '127.0.0.1'` 仅本机可访问；改变配置会触发同次开机重新部署。

## UI 模式

| UI_MODE | 用途 | UI_DIR |
|---|---|---|
| image | 使用镜像内置 UI，默认部署方式 | 必须为空 |
| diagnostic | 只检查环境，不停止或更换小屏 | 保持为空 |
| directory | 只读挂载用户在 NAS 数据盘上的完整前端目录 | NAS 宿主绝对路径 |

旧 Compose 未设置 `UI_MODE` 时，`UI_DIR` 非空按 directory 处理，否则只诊断。旧 `NEW_HTML` 复制参数已停用，请移除。

改变任务配置时递增 `TASK_REVISION`。更换镜像后，镜像 ID 的变化会自动触发同次开机重新执行，不会因旧成功记录而跳过。

## 镜像如何提供 UI

构建时将 `ui/` 和原创 Python 监控/控制服务打包进镜像。容器启动后通过宿主 `docker cp` 读取内置包，先确认 `/run` 及其运行目录确实位于 tmpfs，再验证 SHA256、文件清单、路径、类型与大小限制。在随机暂存目录中校验完成后，原子发布到 `/run/r1-toolbox/ui-<内容摘要>`；复用缓存也重新校验。

宿主小屏临时服务将缓存的 `frontend` 目录通过 `BindReadOnlyPaths` 只读挂载到 `/screen/squashfs-root/resources/app/dist`。挂载仅影响该服务的文件视图，宿主原目录保持原样。Python 服务和 `AppRun` 属于同一临时服务，容器停止或重新创建后均不依赖原容器的文件系统或 PID。设置单独写入数据卷，不写入只读前端。

仅复制、展开到 `/run` 运行目录，不覆盖原版 AppImage、解包版前端或 `/screen/screen-app-startup.sh`。不绑定 Docker 内部镜像层路径，也不要求新版 Compose 的 image volume 语法。

启动前识别 Electron 主进程及其 Chromium 子进程，兼容子进程将命令行改写为一段进程标题的情况。必须只有一个主进程，且所有小屏子进程属于它；多个实例或归属不明时保留现有程序并输出进程诊断。

停原程序前会先用同样的只读绑定属性启动检查服务，确认挂载身份与只读状态。新小屏主进程还需在独立 cgroup 以同一个 PID 和启动时间连续存活 3 秒，并通过自己的 `/proc/PID/root` 文件视图验证挂载。失败时尽力停止新服务，无自定义挂载地恢复原解包程序。

HistorSub 1.1.15 默认创建隐藏窗口。内置 UI 通过官方 `showWin` 显示握手启动窗口定位，收到官方在显示后发出的 `sendAppPath` 回执，再发送 `deviceStatus` 结束定位轮询。普通浏览器预览不发送 Electron 消息；握手脚本独立于状态采集和页面交互加载。容器的进程、挂载检查通过后，仍需确认实机画面与触摸。

## 实时指标与控制

Python 标准库采集 `/proc`、sysfs 与真实数据盘挂载点，基础指标约每 2 秒更新；可选命令在后台分开执行：

- CPU 使用率、可用的 CPU 温度、内存占用、运行时长。
- 默认路由网卡的 IPv4、上下行速率，避免累计 Docker 网桥。
- `/drives/` 下数据盘容量，按文件系统去重。
- CPU 分核、负载、Swap、进程、监听端口、多网卡 IPv4/IPv6、链路速率/双工/MTU 与可用的 GPU sysfs 信息。
- OS/内核/允许列表内的固件版本、DMI、CPU 拓扑/频率、PCI、通用风扇转速、各温度测点、mdraid 状态等设备详情；独立后台低频采集，单项失败不阻塞基础指标。序列号与 MAC 仅在本机展示，不外发。
- 物理磁盘型号、容量、温度与 SMART；使用 `smartctl -n standby -j -a`，结果缓存 30 秒，休眠或不支持时如实显示不可用。
- Docker 容器状态和资源统计；有 `virsh` 且 libvirt 可访问时读取虚拟机状态。

CPU/内存趋势只保留内存中最近 120 次采样，服务退出后清空。设备详情默认约每 30 秒刷新。数据为空、缺工具、接口失效或权限不足时返回原因；独立详细采样失败不会阻塞基础 CPU/网口刷新。没有实际来源的模块隐藏，系统→设备能力仍可查看原因。GPU 利用率和显存字段只在宿主实际提供时显示，不保证当前 Intel GPU 有利用率读数。

API 只监听 `127.0.0.1:18731`。`GET /api/status`、`GET /api/toolbox`、`GET /api/insights` 为读取接口；`POST /api/action` 需要 JSON、允许的 Host/Origin 与 `X-R1-Token`。令牌每次服务启动随机生成，只传给本次启动的 Electron 环境，不写入前端或返回给读取接口。因此普通浏览器预览只有读取能力，控制应在 NAS 小屏操作；当前没有对局域网开放的远程 Web 管理入口。

控制页根据实际能力开放操作：

- 亮度、立即息屏/唤醒、无操作息屏和夜间低亮度；息屏后的第一次触摸仅唤醒，避免误触底下的按钮。实机可能出现原始 `brightness=0` 但画面正常，因此不单凭该值判定息屏。
- 原厂风扇按已加载模块完整 GNU note 验证。已知支持版可用时开放低/中/高/自动系统风扇策略，操作需确认且每次重新核对 note；未知/缺失/旧版只读，失败撤销控制。后台不发送原厂 GET/SET/信号。当前用户 loaded note 已匹配支持版，但旧 RPM 仍不可读，不能据此断定调速失败；模式只影响原厂系统风扇通道，CPU 继续每 10 秒厂商自动温控，不提供会被原厂线程覆盖的 CPU 独立手动/曲线，不擅自停温控服务；物理对应仍待确认。模式1/停转不提供，实际风速变化待观察。
- 受支持的 IT87 hwmon/PWM 通道另提供显式接管：手动 50–100% 占空比，低/中/高 60/80/100%，软件自动或 2–8 点自定义曲线。曲线温度 20–90℃递增、占空比 50–100% 非降；缺 CPU 温度或 ≥80℃请求满速。同号 RPM 为 0 请求满速并显示原因；编号与实际物理风扇的对应仍需确认。当前用户固件未发现这些通道。原厂系统风扇策略与 hwmon 曲线是两条不同路径。
- RGB 先在控制页明确选择 I²C 总线，非强制读取身份 0x26/0x01=0x55、模式0x90及亮度0x91。验证后开放颜色、灯效与0–100%独立亮度，写亮度原始值 round(255×百分比/100)；每次写入前重验，失败撤销旧能力。不扫描所有总线、不带-f，寄存器成功仍需肉眼效果核验。
- Docker 仅启动/停止/重启，保护 Toolbox 自身；VM 仅 start/shutdown/reboot/suspend/resume，不提供删除或强制断电。
- NAS 重启/关机需确认，5 秒内可取消，之后交由固定的 `systemctl` 操作执行。没有 RTC、WOL 或关机后自动开机功能。

设置会持久保存。hwmon 接管、曲线、RGB 验证和待执行电源请求不作为开机自动执行配置保存。退出服务时取消待执行电源请求，并尽力恢复 hwmon PWM/enable、背光/blank 原值；RGB 不自动恢复。用户确认的原厂系统风扇策略会由厂商服务保存，不会因停止 Toolbox 或恢复官方 UI 自动撤销；这是设备设置，与覆盖小屏文件和临时 PWM 接管不同。突然断电或强杀时不能保证恢复逻辑执行。

Python 服务及网页随小屏服务退出；停止宿主小屏服务会同时结束服务与页面进程。若本地状态端口被无关程序占用，新服务会启动失败并尝试恢复原界面；可选网页端口冲突只使网页不可用，不拖垮小屏。不覆盖或结束占用端口的程序。

## 开机一次与恢复

保留 `restart: always`。任务完成或失败后明确调用 Docker 停止当前容器，下次 Docker 启动时再次运行；同次 NAS 开机、相同任务版本、镜像和 UI 配置成功后跳过。成功记录在 `/run/r1-toolbox/last-success`，失败不记录。

恢复官方界面：先删除项目，或将 `restart` 改为 `"no"` 后重新部署，再正常重启 NAS。临时服务、内存 UI 和挂载随重启消失，官方启动流程继续使用原文件。

删除项目时通常可保留独立数据卷；删除项目对应的 `r1-toolbox-data` 卷会丢失 Toolbox 设置，实际卷名可能带项目前缀。卷内只保存 Toolbox 配置，恢复官方 UI 不需要删除该卷。

容器本来就会停止，仅停止容器或改为诊断不会立即撤销已运行的小屏服务。旧版若曾覆盖过 HTML，需要另外恢复当时的备份；内存挂载不会回退历史文件修改。

## 自定义目录模式

将自有界面放在数据盘，例如 `/drives/实际磁盘/R1-Toolbox/ui`，包含 `index.html` 及其引用的 JS、CSS、图片。然后设置：

```yaml
TASK_REVISION: '5'
UI_MODE: directory
UI_DIR: /drives/实际磁盘/R1-Toolbox/ui
```

这是宿主路径，不是 `/host/...`。无需额外添加 Docker volume，已有宿主访问入口会让小屏服务建立私有挂载。目录会遮住服务视图中的整个原版 `dist`，必须提供完整资源。directory 模式直接启动原 AppRun，不额外提供内置 UI 的状态 API。

目录路径支持普通中文，不支持空白、冒号、反斜杠、引号、`%`、`$`、控制字符。源目录不能与目标相同或互为祖先；原子更名整个源目录后需要重跑挂载。

## 依赖、日志与边界

- 宿主需要 `docker`、支持 `--cgroup` 的 `nsenter`、`mountpoint`、`python3`。实际挂载还需要 systemd 233 起的 `BindReadOnlyPaths`、`systemd-run`、`systemctl` 和现有小屏图形环境。以实际预检通过为准。
- 容器名与 `TASK_CONTAINER` 保持 `r1-toolbox`。镜像继承 `docker.io/library/debian:bookworm-slim`，保留原宿主访问机制，不联网安装宿主工具。
- 镜像模式要求 `/run` 为 tmpfs；不满足时在停原小屏前拒绝部署 UI。缺少依赖或包损坏也不会停止原程序。
- 临时服务名打印在容器日志，宿主可用 `journalctl -u histor-custom-<PID>.service` 查看。失败暂存保留至重启，便于排查。
- 执行状态、UI 和采样历史位于运行时目录；Toolbox 设置写入独立数据卷，Electron、系统、Docker 仍可能写正常配置、缓存和日志，不能保证整机零写入。
- 未提供联网天气、SMTP/Server酱、外部 iDRAC、月报/长期历史、fnOS 相册/影视/音乐统计、本地播放器/飞牛音乐代理、视频壁纸/主题编辑器、RGB 温度联动或每日固定时刻的亮熄屏/RGB 计划；没有用占位模块假装实现。完整附件对照见 [功能矩阵](../../docs/features.md) 与 [附件审查](../../docs/attachments.md)。
- 真实 NAS 的画面、触摸、开机时序及厂商守护程序行为需要实机验证。

参考：[systemd 私有挂载](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#BindPaths=)、[Docker cp](https://docs.docker.com/reference/cli/docker/container/cp/)、[Docker 重启策略](https://docs.docker.com/engine/containers/start-containers-automatically/)。
