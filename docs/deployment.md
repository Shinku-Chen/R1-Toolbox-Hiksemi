# 部署与升级

本文归档 R1 Toolbox 的镜像、分支、部署、升级和数据卷约定。快速开始见 [README](../README.md)，运行时细节见 [架构与运行时](architecture.md)。

## 镜像与发布

镜像：`ghcr.io/shinku-chen/r1-toolbox`，平台 `linux/amd64`。

| 标签 | 来源 | 用途 |
| --- | --- | --- |
| `latest` | `main` 已验证提交 | 稳定部署 |
| `preview` | `dev` | 预览与新功能验证 |
| `sha-<完整提交>` | 每次构建 | 固定版本、回滚和问题复现 |

同一提交从 `dev` 推进到 `main` 时，发布流程复用已有 SHA 镜像，重新校验并更新 `latest`，不覆盖不可变的 SHA 标签。具体构建和检查步骤见 [开发与测试](development.md)。

## 前置条件

- 海康 R1 NAS，官方固件，x86_64。
- 可用的 Docker／Compose 环境。
- 可写的独立数据卷 `r1-toolbox-data`。
- 局域网内可访问 NAS 的电脑或手机。
- 建议先在非关键数据环境验证；不要在生产数据盘上直接尝鲜。

## 在线部署

1. 从 [Actions](https://github.com/Shinku-Chen/R1-Toolbox/actions) 下载成功构建的产物。
2. 在 NAS Docker 管理页用产物中的 `composer.yml` 创建或更新项目。
3. 启动容器。
4. 打开 `http://NAS_IP:18732`。

容器应持续运行。`UI_MODE: image` 使用镜像内置小屏界面，不需要上传前端目录；`UI_MODE: diagnostic` 不接管小屏，只运行网页核心服务。

## 离线部署

1. 下载同一产物的 `r1-toolbox-linux-amd64.tar` 和 `composer.yml`。
2. 在 NAS 上导入 `r1-toolbox-linux-amd64.tar`。
3. 用 `composer.yml` 创建项目并启动。

发布包的 Compose 固定对应源码提交的镜像，不需要 `.env`，也不强制联网重新拉取。

## 首次登录

默认 `R1_WEB_AUTH_MODE: password`：

- 首次没有口令，能访问 `18732` 的局域网设备可直接管理。
- 建议在“设置 → 登录口令”设置至少 6 位口令并开启。
- 设置口令后，网页写操作需要登录会话；同源、JSON 和 CSRF 校验始终保留。
- 需要兼容旧五位配对流程时，显式设置 `R1_WEB_AUTH_MODE: pair`。
- 认模式会话最长 8 小时；口令会话按设置保持 1–30 天。

网页使用局域网 HTTP；口令负责授权，不负责传输加密。只应在可信局域网使用。

## 服务开关

- 小屏默认开启；关闭后恢复官方显示，网页、MCP、风扇和灯光继续运行。
- MCP 默认关闭；开启后在“设置 → API 管理”创建独立 Token。
- 开发者模式默认关闭；只用于固定诊断，不接受任意 Shell。

这些设置以网页“设置 → 服务与开发”保存值为准；Compose 中的开发环境变量只在尚无持久设置时初始化。

## 数据卷

- 面板、风扇、灯光、统计、服务开关、开发窗口、Token 摘要和显示缓存保存在 `r1-toolbox-data`。
- 升级、重建和回滚必须复用原 Docker 项目与原数据卷。
- **不要执行 `down -v`，不要删除数据卷。**
- 删除部署后正常重启可恢复官方显示。

## 升级与回退

1. 拉取目标镜像标签（优先固定 `sha-*`）。
2. 在 Portainer／Docker 管理页重新创建容器，勾选重新拉取镜像，保留原 Compose 和数据卷。
3. 启动后核对“服务与开发”中的实际小屏／MCP 状态，不要只看开关勾选。
4. 若出现异常，回退到上一个已验证的 `sha-*` 镜像，继续复用同一数据卷。

不要并行创建第二套容器或新卷；单实例锁会阻止宿主出现第二套核心，但并行部署仍可能造成端口和恢复流程冲突。

## 开发者 Compose

`composer.dev.yml` 是独立完整示例：

- 使用 `preview` 镜像。
- 启用受限诊断命令。
- 初始化开发窗口 1440 分钟。
- 必须提供 `R1_DEV_ALLOW_IPS`（局域网 IP 或 CIDR），不内置个人地址。
- 与通用 `composer.yml` 使用相同服务、容器和数据卷。

开发白名单只用于固定只读诊断；不授予 MCP Token、网页登录或风扇重试。详见 [开发者白名单检测](dev-diagnostics.md)。

## 常见检查

| 现象 | 检查 |
| --- | --- |
| 网页打不开 | 容器是否持续运行、`18732` 是否被占用、`R1_WEB_PORT` 是否为有效端口 |
| 小屏没有接管 | “服务与开发”的实际 `active/busy/last_error`，不要只看开关 |
| 硬盘数据为 `--` | 是否有合法缓存、是否休眠、是否刚进入页面正在补齐 |
| 风扇手动不可用 | 预检是否通过；自动／原厂模式不需要独立接管 |
| 更新后配置丢失 | 是否复用了原项目与原 `r1-toolbox-data` 卷 |
| MCP 连接被拒 | MCP 是否开启、Token 角色／功能域／来源是否匹配 |
