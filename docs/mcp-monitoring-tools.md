# MCP 缓存监控工具

三项工具均要求 `readonly` 或以上、`read` 域及精确工具授权。旧 policy v1／v2 仍只有原十工具；增加工具不会扩权。监控实现只调用已有内存缓存访问器，不读取历史数据库、不采样、不查询原厂业务、不运行 SMART 或主动唤盘采集。API 鉴权与审计仍使用原独立数据卷，因此不承诺整个 HTTP 请求没有磁盘 I/O。

| 工具 | 参数 | 返回与缺测语义 |
| --- | --- | --- |
| `get_monitoring_history` | 必填 `metric`；`range` 为 `10m/1h/6h/24h/7d/30d`，默认 `1h`；`limit` 为 `1～720`，默认 `720` | 单指标最多七百二十个 `[Unix 秒, 数值或 null]` 点；返回既有 `last` 聚合、记录状态、截断、有效与缺测点数。`projection_complete` 仅表示投影未遇非法值，不保证采样连续，`sampling_continuity` 固定 `not_asserted`。不插值、不补零 |
| `get_health_events` | 可选 `limit` 为 `1～100`，默认 `50`；`since` 为非负 Unix 秒 | 当前告警与最近事件来自同一锁内的缓存代；SMART 标识再散列，不返回序列号、动态标签、原始 SMART、路径或诊断文本。超过九十秒、未来或缺少采样时间时评估为 `unknown`；有缺测时不能报 `ok`，已有新鲜 `warning/critical` 可保留。`assessment_complete` 与条目投影 `complete` 分开 |
| `get_network_traffic_totals` | 无参数 | 日／月已观测计数增量，逐接口与原缓存汇总分开返回，不再相加；未观测时段、计数重置及断电缺口不估算。未知累计量为 `null`，保留 `partial` 和 `observed_counter_deltas` 口径 |

历史只允许十一项固定指标：CPU／内存使用率、已计网口接收／发送速率、CPU／硬盘最高温度、RAPL CPU 封装功耗、物理盘读／写速率、CPU／系统风扇请求输出。动态传感器身份不进入此接口；风扇百分比不是 RPM，封装功耗不是整机功耗。

健康工具只反映本地已观测指标，没有告警不能证明未采集的硬件健康。只读投影只返回白名单字段，无法识别的告警条目计入拒绝数并标记不完整，不以空列表冒充完整无告警。读取前后都复核当前 Key、授权修订、凭据代际和服务代，操作中撤销、轮换、停用或关闭 MCP 后丢弃结果。

2026-10-30 在运行 `sha-45e75d3` 的 NAS 上，通过已有只读历史和流量 API 校对新投影：CPU 一小时历史返回一百一十九点，流量缓存有两个接口。该核对只验证真实缓存格式和投影，不表示新 MCP 工具已部署；健康的同代访问器及 Token 接线须随新镜像验收。

自动验证：`python -B -m unittest discover -s tests -p test_api_monitoring.py -v`，覆盖缓存零值／缺测／异常、样本边界、私有字段、同代健康快照、过期与不完整评估、流量独立口径、真实 MCP／REST、旧键隔离和读取期间撤权。
