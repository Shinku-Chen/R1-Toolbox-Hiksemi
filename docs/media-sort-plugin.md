# 影视追更排序

网页“设置 → 影视追更排序”提供内置可选插件。它针对已审计的原厂影视中心数据库，调整电视剧的排序时间，让已识别电视剧出现新路径时有机会进入电视端“最近添加”前列。Toolbox 不替换影视中心程序或电视客户端，实际列表顺序仍需用真实更新验收。

## 使用流程

1. 点击“检测数据库”。服务只从正在运行、身份匹配的原厂 `scraper` 进程读取 `-d` 数据目录，不搜索媒体目录，不要求填写路径。
2. 核对数据库位置并选择候选。多个数据库分别展示，不默认选择第一个；无法核验的候选不可写。
3. 点击“应用追更排序”并确认。若检测到已识别的旧版规则，按钮显示“确认升级追更排序”。后台先创建私有一致性备份，再以一个 SQLite 事务安装或升级固定规则。
4. 需要停止增强时，点击“撤销增强”并确认。撤销仅删除精确识别的插件触发器与影子表，不恢复整份旧数据库，不覆盖此后新增的媒体；已经调整的排序时间保留。

打开设置只读取 Toolbox 内存缓存。“读取缓存”也不扫描原厂进程或数据库。点击检测、应用、升级、撤销才访问原厂数据，可能唤盘或触发 SQLite 辅助文件的元数据变化。没有周期检测、自动应用或启动时重装。规则存放在原厂数据库中，因此 NAS／Toolbox 重启后继续存在；停止 Toolbox 容器不会撤销它。

网络超时、连接中断或结果未知时，页面不会重发写操作，并禁用应用／撤销，直到手动重新检测。缓存状态表示上次检查结果，不证明此刻数据库仍未变化。检测结果只绑定本进程中的候选 ID 与版本，Toolbox 重启或来源变化后需要重新检测。

## 排序规则与局限

v2 仅处理 `metadata.type` 为 `2`／`4` 的电视剧。它兼容原厂 `INSERT OR REPLACE` 和路径更新，以同一媒体 ID、媒体库 ID 的已观察路径集合为基线。新路径出现时调整 `timestamp`，重复路径、数组重排和纯资料刷新不置前；相同数量的路径被新路径替换也可以识别。`2 → 4` 类型切换保留可比较的路径基线。

初次安装只建立已有内容的基线，不把全部旧剧置前。没有旧基线的新记录保留原厂时间；损坏或不是字符串数组的 JSON 不触发增强，也不因插件的 JSON 调用阻断原厂入库。同一媒体库存在不明确的类型聚合时拒绝安装。

路径不是经过验证的单集身份或真实首次入库时间。插件不能恢复过去的更新历史，不能检测同一路径中文件内容的覆盖，也不能保证路径改名代表新一集。删除再加入已观察过的路径不会再次置前。跨媒体库的聚合顺序仍由原厂客户端决定。

## 备份与撤销

备份位于 Toolbox 网页状态目录下的 `media-sort-backups/`，私有目录权限为 `0700`，随机、独占创建的备份文件为 `0600`。使用 SQLite 在线备份读取一致的已提交状态，包含 WAL 中的已提交数据；备份失败不应用规则。页面展示本次 Toolbox 进程已成功记录的最近备份位置，重启后该显示缓存清空，已有备份文件继续保留，不扫描或自动清理。

撤销不是整库恢复按钮。需要人工恢复备份时，应先停止原厂写入并核对备份与后续数据，不能在原厂运行中覆盖数据库。产品接口不接受备份路径、任意 SQL 或整库恢复请求。

旧实验中的 `metadata_touch_updated` 仅监听 UPDATE，不能覆盖原厂替换插入流程，不作为受支持规则接管。严格识别的旧版 `metadata_guard_insert` 与 `metadata_path_guard` 只在所有者确认后处理；同名未知对象、混合残留或额外未知媒体触发器均报告冲突，不擅自接管或删除。

## 接口与授权

| 接口 | 请求体 | 行为 |
| --- | --- | --- |
| `GET /api/plugins/media-sort` | 无参数 | 只读 Toolbox 内存缓存，不打开原厂库。 |
| `POST /api/plugins/media-sort/probe` | `{}` | 显式发现并核验候选。 |
| `POST /api/plugins/media-sort/apply` | `candidate_id`、`version`、`confirmed:true` | 已选候选的备份与应用／升级。 |
| `POST /api/plugins/media-sort/revert` | `candidate_id`、`version`、`confirmed:true` | 撤销精确识别的规则，不回滚媒体数据。 |

这些接口仅接受当前网页所有者：默认 `password` 模式尚未设置口令时与其他网页管理一致直接可用；启用口令后需登录，显式 `pair` 模式需配对。保持真实来源、同源、JSON 与 `X-FNM-Request: 1`／配对 CSRF 校验。Bearer Token、MCP 和开发者白名单不能管理此插件，不能把已有原厂登录 Token 转成插件授权。

后台限定已审计 `scraper` ELF、进程启动生命周期、命名空间与根视图，并逐级 no-follow 打开数据路径，核验真实 SQLite 主文件句柄、辅助文件、属主／权限、完整表结构与 JSON1。来源不匹配、路径替换或未知结构时拒绝操作，不修改原厂目录权限。候选路径和备份位置只返回所有者，不进入公开快照、小屏、MCP、默认诊断或审计参数。

应用、升级、撤销在执行、提交和返回前重复核验来源及所有者授权。提交后断线或撤权仍可能已经完成数据库事务，应重新检测，不能按错误响应断言未写入。服务停止只关闭授权与后台操作，不自动撤销已提交规则。

## 验证状态

本功能配有 SQLite 规则回归、后端备份／事务／权限检查、真实 HTTP 授权与撤权回归，以及独立浏览器交互检查。Linux 文件句柄检查以 Linux CI 为准。

已有 NAS 的旧版 INSERT guard 来自用户此前的明确应用，真实新一集及电视端前移尚未完成验收；新插件不会自动重复安装或升级。实机先显式检测，再核对候选状态、版本和备份，确认后才写入。
