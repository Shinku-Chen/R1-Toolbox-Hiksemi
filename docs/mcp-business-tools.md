# MCP 业务状态工具

应用、下载和媒体已有经过验证的脱敏来源，本轮将其接成五个分域只读工具。
这些工具仅返回已有观察结果；调用本身不发起原厂查询、下载器联网刷新或任务操作。
本页只描述五项缓存工具；它们的查询语义保持不变。当前全目录三十六项，另外接入的显式下载、媒体及固定项目操作见[业务操作](mcp-business-operations.md)。文件／Docker 二十项合同中七项已有执行器，十三项文件操作待接入。

## 工具与来源

五个工具均只接受空对象 `{}`，声明 `readOnlyHint=true`，最低角色为 `readonly`。

| 工具 | 功能域 | 固定来源与实际范围 |
|---|---|---|
| `get_app_status` | `apps` | `vendor_app_diagnostics.collect`：Toolbox 最近显式应用快照，必要时读取原厂 NAND 已有安装缓存；部分历史目录，运行状态保持 `null`。 |
| `get_download_status` | `downloads` | 当前服务已发布的业务快照中的下载类别；分开保留 aria2／qB 的成功数据与失败状态。不调用下载采集器，不登录下载器。 |
| `get_movie_status` | `movie` | Toolbox 媒体缓存中的 `scraper`，只含已采集的影视刮削计数与原生状态码。 |
| `get_album_status` | `albums` | 同一媒体缓存中的 `face`、`ocr`、`thumbnail`、`similar`、`ai`，只含已采集的处理进度与配置状态。 |
| `get_share_status` | `sharing` | 同一媒体缓存中的 `shared_album`，只含固定管理员既有共享相册的处理状态，不是分享列表。 |

应用与媒体使用现有安全缓存读取器，仍校验固定文件、大小、结构与脱敏字段；再复用业务诊断的字段投影。
它们不会签名原厂请求、读取原厂会话库、重新登录或导入查询动作。
下载读取由 `business_state_lock` 保护的已发布快照，校验发布代次；来源刷新已使旧快照失效时，返回未采集。
尚无下载快照或服务重启后，不为 MCP 补采数据。现有网页／业务采集可以产生下一份快照；其固定监听身份核验、回环连接、认证和超时边界保持原样。

## 返回语义

共同外层包含 `ok`、`read_only`、`cached`、`available`、`status`、`source`、`reason`、`freshness`、`last_failure` 与 `data`。

- `ok=true` 仅表示缓存查询正常完成；必须继续检查 `available`、`status` 和具体字段。
- `freshness.observed_at` 为实际缓存观察时间，`age_seconds` 为可计算的快照年龄，`live=false`，`refresh=not_requested`。这不是实时性保证，也没有隐式到期后自动刷新。时间未知、缺少时区或观察时间晚于当前时间时，无法确认的年龄保持 `null`。
- 缓存整体未采集、无效或不可读取时返回不可用与 `data=null`；已有媒体缓存中单项未采集或失败时保留该项状态，项内 `data=null`。未知任务数、进度和大小保持 `null`，不会以零任务推断空闲。
- 应用目录明确 `complete=false`；有安装缓存不代表应用正在运行。最近显式刷新失败时，保留错误码和尝试时间；历史安装缓存与失败并列呈现。
- 下载保留各引擎的独立状态，不合并任务标识或计数，也不返回文件名、磁力链接、路径、凭据、SID 或原始上游结果。`last_failure` 列出已记录的失败引擎和该快照时间。
- 媒体结果仅返回当前域的固定项目，不返回其它域的记录或全局覆盖统计。外层观察时间为本域最近一次项目观察；每项保留 `captured_at`、自己的 `freshness` 和 `last_failure`。部分刷新不替其它项目更新观察时间，恢复成功后仍保留最近一次失败。
- 共享相册不存在时为 `not_applicable`，不返回零计数，也不创建相册或样本。原厂共享计数有已知吞错零值，缓存中的零值不能证明空闲。

`get_media_status` 保留原行为：它属于 `media` 域，最低角色为 `readwrite`，显式执行原厂媒体查询，可能写完成状态或触发修复分支，`readOnlyHint=false`、`idempotentHint=false`。
新五工具不会调用它。原 `get_nas_status` 的 `apps` 状态类别也保留兼容行为；新工具提供单独 `apps` 域的最小授权入口，不重复新增一组广域状态工具。

## 授权与并发失效

工具列表和调用均通过 `api_permissions.permission_allows`，角色、功能域与具体工具三者共同授权。
管理员也不能跨域；`read` 或 `media` 域不会自动授予新的业务工具。
所有者必须在 API 管理中选择具体工具，生成或显式升级为 policy v3；policy v1／v2 继续冻结原十工具，预先勾选业务域、改名、轮换或修改角色都不会自动获得新工具。
旧业务域授权在能力目录中显示 `pending_enable`。

新业务读取与现有资源读取一样，在开始前与返回前调用 `ApiAccessStore.is_current`。
读取期间撤销、停用、轮换、修改域／工具／IP 策略、到期或关闭 MCP，已取得的数据会被丢弃，只返回固定 `invalid_key`。
审计仅记录已知工具名、结果类别、来源地址和耗时，不保存参数、业务结果或凭据。

## 尚未实现的完整业务能力

五个缓存工具本身始终不触发业务写入。另有精确工具执行下载任务暂停／继续／移除／限速、相册创建／改名、影视库改名与分享撤销。应用安装／卸载、新增下载任务、影视来源配置、照片内容和分享创建仍未接入，没有占位回调。
备份和系统管理保持待接入。Docker 有已登记项目读取、管理员启停重启和受控镜像更新；通用新建部署尚未接入，管理员不能越过项目操作范围。
文件根仍仅提供授权范围内绑定元数据；文件读取、浏览、传输与写入等待真实 ACL、安全打开与句柄验证闭环。

验证采用临时缓存和真实本机 HTTP 服务，不访问 NAS。`tests/test_mcp_business_tools.py` 覆盖来源投影、分域隔离、列表／调用一致、旧键隔离、缺失／部分数据、最近失败与读取中授权失效；现有权限、MCP、集成 HTTP 套件继续验证原工具和传输边界。
尚未覆盖真实 NAS 上缓存的新鲜程度、原厂业务结果的正确性和实际硬件行为；这些需要所有者显式采集后对照缓存验收，不由 MCP 自动探测补足。
