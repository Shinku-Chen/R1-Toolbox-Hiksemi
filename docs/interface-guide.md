# 小屏与网页使用说明

本版将常用查看和简单操作留在小屏，把多来源温控、灯光节点和统计阈值放在网页。参考图片与 HTML 用于视觉和信息层级参考，界面、数据采集与控制后端独立实现；显示的是这台 NAS 实际可读到的数据。

## 小屏入口

底部保留“概览、存储、网络、控制、应用、系统、设置”七页，也可左右滑动切换。点击条目进入详情，通过返回键或详情中的返回手势回到上一级。阅读详情时可上下滚动。

顶部“控制”按钮或在页头区域向下滑动，可进入控制中心，再打开屏幕、风扇、灯光或电源二级页。控制中心的“返回”回到来时页面，保留原详情与滚动位置。页头手势不要求在详情正文中下拉。

小屏可调亮度、立即息屏，并查看两路风扇和灯光当前状态。灯光按已知设备身份自动识别，不需要选择 I²C 总线；不能唯一确认设备时不开放即时写操作。多温度来源、各路阈值、灯光颜色节点、夜间计划等复杂设置，从“设置 → 网页配置”进入网页完成。风扇输出百分比是请求值，不是已测到的 RPM；未知 RPM 保持未知。

## 打开 Docker 容器

小屏进入底部“应用”页，宿主 Docker 可读时会直接显示运行中／已发现容器总数和最多六项容器预览。点击容器卡片打开详情；“Docker 容器”入口打开完整列表，再点击某个容器查看详情。

网页进入“应用”页，可搜索容器、按状态筛选，点击容器打开详情。列表和详情共享相同的状态与操作限制。公开监控可直接查看，启停操作需要先配对。

容器信息包括名称、镜像、状态、Docker 返回的端口文本，以及能读取到的 CPU、内存统计。Docker 服务不可用或权限不足时显示原因；统计单独失败不会把已有容器列表藏掉。首次采集或缺测显示未知，不补成零。容器 CPU 可以超过 100%，例如同时占用多个逻辑核心。

端口来自 `docker ps` 的实际 `Ports` 字段。例如 `127.0.0.1:8080->80/tcp` 表示发布到宿主回环地址；单独的 `80/tcp` 只表示容器暴露端口。空字段表示 Docker 未提供映射文本，不能据此判断应用没有监听。系统页的“监听端口”来自宿主 `/proc/net`，与容器端口映射是不同的数据源，不推测它属于哪个容器，也不把端口自动变成服务链接。

## 启动、停止与重启

| 当前容器状态 | 提供的操作 |
|---|---|
| 运行中 `running` | 停止、重启 |
| 已停止 `exited`／新建 `created` | 启动 |
| 暂停、重启中、删除中、异常或未知 | 仅查看，等待真实状态更新 |
| 受保护的 Toolbox 部署容器 | 仅查看，到 NAS 管理页管理部署 |

点击操作后需明确确认。执行前后端会再读取容器 ID、当前状态及保护标记；如果 NAS 管理页已改变状态，原来的按钮不能直接授权另一次操作。两端共享同一后端，不会因从网页进入而绕过保护。Toolbox 容器按保留名称或 Compose 服务标签识别，普通改名不能绕过其标签保护。

停止、重启沿用 Docker 的优雅停止机制，没有添加强制操作或改变容器的停止超时配置。后端为这两项命令最多等待15秒；如果容器本身需要更久，界面提示“结果未确认”，后台请求重新读取列表。命令退出成功后仍需等待刷新，不提前把旧状态画成目标状态。命令非零退出会标记失败；接口可返回退出码，不向网页泄露原始命令输出。

看到“正在执行”时等待结果；看到“结果未确认”时先刷新、核对当前状态，再决定下一步。界面和后端不会自动重发启停命令；并发操作会立即提示忙，不在请求超时后继续排队执行。这里不提供创建、删除、更新镜像、`exec`、`prune` 或 Compose 编辑，复杂 Docker 管理继续使用 NAS 自带管理页。

## 打开网页与解锁设置

1. 在小屏进入“设置 → 网页配置”，查看当前可访问地址。默认格式是 `http://NAS的IPv4地址:18732`，使用小屏显示的真实地址，不把示例文字当成地址。
2. 在同一局域网的电脑或手机打开地址。概览、存储、网络、应用、设备和趋势等公开监控无需配对。
3. 修改设置或执行容器操作时，选择网页的“解锁设置”，再在小屏点击“生成一次性配对码”。输入显示的五位数字，包括开头的零。
4. 配对码三分钟有效、只能使用一次；重新生成使旧码失效。离开小屏配对页后不再显示。网页会话只在本次服务运行期间有效，最长八小时；退出登录或服务重启后需重新配对。

网页使用局域网 HTTP，配对解决的是操作授权，不加密局域网传输。应在可信的本地网络使用，公开监控与配对设置共用此监听端口。可在 Compose 中通过 `R1_WEB_PORT=0` 禁用网页，或用 `R1_WEB_BIND=127.0.0.1` 只监听本机；详见[部署说明](../tools/boot-once/README.md)。

配对后可使用控制中心和分组设置页。面板外观、字号、页面轮播与息屏参数按区保存；独立风扇和灯光配置区分“保存待用规则”和“应用”。只保存不接管设备，也不替换此前成功应用的开机恢复规则。硬件能力没有验证时，相关写操作隐藏或不可用；风扇、灯光配置仍可保存为待用规则，但不能把保存回执当成硬件已生效。

配置保存在部署使用的独立数据卷，重建或升级 Docker 项目时应复用原卷。浏览器 Cookie 仅用于会话，不保存设置；重新登录后从宿主服务重新读取。部署容器完成后停止，网页与小屏由 RAM 中的宿主服务继续运行，不需要把部署容器一直挂着。

## 读数与验证范围

界面只显示可核对的真实来源。SMART 休眠盘不会因网页刷新被唤醒；过期读数不会因页面刷新变新。历史曲线断点表示没有有效采样，不能补算未监控时段。无法读取的传感器、CPU封装功率等专属模块按能力隐藏或注明原因；CPU封装功率不代表整机功耗。

本版的界面、鉴权、容器状态变化和失败路径由隔离浏览器与假命令测试覆盖，发布流程另检查 Linux 镜像内的真实打包和宿主服务生命周期。这些检查不等于已经在用户 NAS 上验证灯光肉眼效果、风扇机械响应或全部容器业务。功能与实机边界见[功能矩阵](features.md)，复杂设置另见[独立温控](fan-policy.md)、[灯光策略](light-policy.md)和[监控统计](monitoring.md)。
