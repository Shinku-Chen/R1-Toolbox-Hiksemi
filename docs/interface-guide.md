# 小屏与网页使用说明

本版将常用查看和简单操作留在小屏，把多来源温控、灯光节点和统计阈值放在网页。参考图片与 HTML 用于视觉和信息层级参考，界面、数据采集与控制后端独立实现；显示的是这台 NAS 实际可读到的数据。

## 小屏入口

底部保留六个大标签：“概览、存储、网络、应用、温度、设置”，可直接点按，也可左右滑动切换。主页面不显示顶部栏；点击卡片进入核心指标、处理器与内存、历史趋势、容器、监听端口、网页设置或电源管理等详情，详情页只保留返回栏，通过返回键或右滑回到上一级；阅读详情时可上下滚动。所有主要点击目标不小于 56px，正文 22px、导航 18px，适合手指操作。

“温度”页可查看传感器、每块物理硬盘温度和风扇状态，并分别快速切换 CPU／系统风扇；六个底部图标与网页一致。“设置”页可调亮度与自动息屏、拖动灯光色相与亮度、选择四种原生灯效、进入网页设置。重启和关机放在设置页的“电源管理”二级页，进入后仍需再次确认。

小屏可调亮度、立即息屏，分别快速切换两路风扇的自动／低／中／高／手动模式，调节手动灯光的色相、亮度和模式，并执行带确认的关机／重启；触摸、按键和滚轮会刷新息屏计时，操作中不会因旧的空闲计时突然待机；风扇曲线、温度来源、登录口令等复杂设置只在网页提供；灯光只提供关闭、常亮、彩虹、呼吸四种原生模式，不提供温度联动或状态色编辑。手动风扇需要网页已保存温度来源；未配置时小屏只允许自动和固定档。快捷提交后显示“正在应用”，应用失败会保留后台原因，不把提交回执当成已生效。灯光按已知设备身份自动识别，不需要选择 I²C 总线；不能唯一确认设备时只显示状态。风扇输出百分比是请求值，不是已测到的 RPM；未知 RPM 保持未知。

## 打开 Docker 容器

小屏进入底部“应用”页，宿主 Docker 可读时直接显示运行中／已发现容器总数和完整容器列表，不再先显示三项预览或经过二级“全部容器”页面。点击容器卡片打开详情，返回时恢复列表滚动位置。

网页进入“应用”页，可搜索容器、按状态筛选，点击容器打开详情。列表和详情共享相同的状态与操作限制。公开监控可直接查看，启停操作需要先配对。

容器信息包括名称、镜像、状态、Docker 返回的端口文本，以及能读取到的 CPU、内存统计。Docker 服务不可用或权限不足时显示原因；统计单独失败不会把已有容器列表藏掉。首次采集或缺测显示未知，不补成零。容器 CPU 可以超过 100%，例如同时占用多个逻辑核心。

小屏“应用”页会保留 Docker 的具体读取失败原因，同时隐藏过期列表和管理入口，数量显示为未知；这与成功读取后发现 0 个容器不同。连接恢复后自动重新读取，状态确认前不开放操作。

端口来自 `docker ps` 的实际 `Ports` 字段。例如 `127.0.0.1:8080->80/tcp` 表示发布到宿主回环地址；单独的 `80/tcp` 只表示容器暴露端口。空字段表示 Docker 未提供映射文本，不能据此判断应用没有监听。系统页的“监听端口”来自宿主 `/proc/net`，与容器端口映射是不同的数据源，不推测它属于哪个容器，也不把端口自动变成服务链接。

## 启动、停止与重启

| 当前容器状态 | 提供的操作 |
|---|---|
| 运行中 `running` | 停止、重启 |
| 已停止 `exited`／新建 `created` | 启动 |
| 暂停、重启中、删除中、异常或未知 | 仅查看，等待真实状态更新 |
| 受保护的 Toolbox 部署容器 | 仅查看，到 NAS 管理页管理部署 |

点击操作后需明确确认。执行前后端会再读取容器 ID、当前状态及保护标记；如果 NAS 管理页已改变状态，原来的按钮不能直接授权另一次操作。两端共享同一后端，不会因从网页进入而绕过保护。Toolbox 容器按保留名称或 Compose 服务标签识别，普通改名不能绕过其标签保护。

停止、重启沿用 Docker 的优雅停止机制，没有添加强制操作或改变容器的停止超时配置。考虑到原厂 Docker 读取列表可能需要十余秒，操作前状态核验和启动命令各最多等待 20 秒，停止／重启命令最多等待 30 秒；两端为整个操作请求保留 60 秒等待时间。如果仍未完成，界面提示“结果未确认”，后台请求重新读取列表。命令退出成功后仍需等待刷新，不提前把旧状态画成目标状态。命令非零退出会标记失败；接口可返回退出码，不向网页泄露原始命令输出。

看到“正在执行”时等待结果；看到“结果未确认”时先刷新、核对当前状态，再决定下一步。界面和后端不会自动重发启停命令；并发操作会立即提示忙，不在请求超时后继续排队执行。这里不提供创建、删除、更新镜像、`exec`、`prune` 或 Compose 编辑，复杂 Docker 管理继续使用 NAS 自带管理页。

## 打开网页与解锁设置

网页直接使用 [fnMonitor](https://github.com/MisiteQ/fnmonitor) 的面板框架，磁贴、点阵数字、详情抽屉、布局编辑与设置方式与上游一致；导航重组为与小屏一致的六个标签（概览／存储／网络／应用／温度／设置）。R1 的双路风扇、机身灯光、小屏与电源以新增磁贴和设置分组加入。完整说明见[网页面板](web-panel.md)。

1. 在小屏进入“设置 → 网页设置”，查看当前可访问地址。默认格式是 `http://NAS的IPv4地址:18732`，使用小屏显示的真实地址，不把示例文字当成地址。
2. 在同一局域网的电脑或手机打开地址。概览、存储、网络、应用、温度与设置等页面默认公开只读（若已开启登录口令，则先登录）。
3. 宿主默认使用登录口令模式，网页写操作不再要求配对码；口令默认关闭，可在网页设置中启用。需要兼容旧流程时可在 Compose 设置 `R1_WEB_AUTH_MODE: pair`。
4. 配对模式下配对码三分钟有效、只能使用一次；重新生成使旧码失效。离开小屏配对页后不再显示。配对会话只在本次服务运行期间有效，最长八小时；退出登录或服务重启后需重新配对。
5. 也可以在网页“设置 → 登录口令”开启可选口令登录（至少 6 位）。开启后访问面板先输入口令；口令会话按设置保持 1–30 天，不保存明文。

网页使用局域网 HTTP，配对与口令解决的是操作授权，不加密局域网传输。应在可信的本地网络使用，公开监控与授权设置共用此监听端口。可在 Compose 中通过 `R1_WEB_PORT=0` 禁用网页，或用 `R1_WEB_BIND=127.0.0.1` 只监听本机；详见[部署说明](../tools/boot-once/README.md)。

解锁后可使用全部设置页。网页外观、主色、字号、点阵数字、布局与提醒阈值保存在 NAS 的面板界面文件；小屏本身不再提供外观、页面或夜间设置，亮度与息屏在设置页即时调整。风扇只有一个“保存”按钮，点击即保存并应用，不再弹出确认或要求复位；手动直接进入温控曲线，固定输出从高／中／低选择。同一组已接管通道改档或修改曲线直接更新目标，必要的初次接管、通道变更、原厂设档交接和安全保护仍保留。灯光保存维持确认。硬件能力没有验证时，相关写操作隐藏或不可用；保存回执不等于硬件已生效，运行状态仍需确认。

风扇保存前会显示能否应用及具体原因。连接中断、已有操作正在执行，或固件／驱动／原厂进程等预检未通过时，保存保持禁用。原厂策略配置允许末尾的空字节填充，读取时兼容该格式，原厂文件保持原样。更新镜像后需刷新网页并重新配对，确认接口已验证，再明确应用此前保存的规则。

配置保存在部署使用的独立数据卷，重建或升级 Docker 项目时应复用原卷。浏览器 Cookie 仅用于会话，不保存设置；重新登录后从宿主服务重新读取。部署容器完成后停止，网页与小屏由 RAM 中的宿主服务继续运行，不需要把部署容器一直挂着。

## 读数与验证范围

界面只显示可核对的真实来源。小屏温度页读取后台已有的硬盘温度，不临时启动 SMART：休眠盘有旧读数时标注缓存，无读数保持 `--`。SMART 休眠盘不会因网页刷新被唤醒；过期读数不会因页面刷新变新。历史曲线断点表示没有有效采样，不能补算未监控时段。无法读取的传感器按能力隐藏或注明原因；网页不展示CPU封装功耗、显卡和能耗卡片，风扇转速未知时不伪造读数。

本版的界面、鉴权、容器状态变化和失败路径由隔离浏览器与假命令测试覆盖，发布流程另检查 Linux 镜像内的真实打包和宿主服务生命周期。这些检查不等于已经在用户 NAS 上验证灯光肉眼效果、风扇机械响应或全部容器业务。功能与实机边界见[功能矩阵](features.md)，复杂设置另见[独立温控](fan-policy.md)、[灯光策略](light-policy.md)和[监控统计](monitoring.md)。
