# 三端数据覆盖与缺口

本表核对 `insights`、`device_info`、`fnm_compat`、小屏 `panel.js`、网页 R1 模块及 MCP 实际回调，日期为 2026-10-29。代码和 fixture 通过表示链路具备实现，不表示本轮已在 NAS 验收；本轮不访问 NAS。

状态须分清：**已接入**表示真实来源已有采集和投影；**可填但未接入**表示已有可读来源，仍缺口径或字段映射；**来源未验**表示有实现但缺当前 NAS 证据；**未实现**表示没有执行器；**未知**表示该次来源未返回有效值。未知与未实现均不能补成零值、空闲或健康，也不增加占位卡。

| 数据 | 真实来源与状态 | Web | 小屏 | MCP／REST |
|---|---|---|---|---|
| CPU、分核、内存使用、负载、运行时间 | `/proc` 与 CPU sysfs，已接入；首个差值样本可未知 | 概览、进程、硬件信息 | 概览、指标、CPU 详情 | `get_nas_status` 概览／系统 |
| 网口地址、速率、MAC、实时流量 | `/proc/net`、sysfs，已接入；缺驱动字段保持未知 | 网络与主机信息 | 网络及接口详情 | 状态网络；不提供网络配置执行器 |
| 磁盘型号、容量、温度、SMART、休眠 | sysfs 与后台 `smartctl -n standby`，已接入；休眠时不临时补测 | 物理盘卡与 SMART 详情 | 物理盘与温度；不提供完整 SMART 属性表 | 状态存储／温度；不执行按需 SMART |
| 磁盘名称、空间名称 | 当前设备身份与原厂固定 `get_disk_list;`／`get_space_list;` 唯一匹配，已接入 | 盘卡名称 | 盘卡、温度列表 | 状态存储／温度；RAID 空间名不冒充单盘昵称 |
| **完整硬盘 SN** | **本轮补齐**：背景采集时交叉核验现有 sysfs／udev／SMART 身份与固定原厂列表，保存在私有缓存 | 仅已授权面板的概览与 SMART 详情显式读取；冲突或换盘为 `null`，不回退旧 sysfs 值 | 不新增完整 SN | 不新增完整 SN；默认公开 v1 与默认开发快照同样不新增 |
| 温度来源、风扇状态与 RPM | hwmon／受限控制器，已接入；无测速证据则 RPM 未知 | 温度与双路风扇 | 温度、风扇档位 | 状态温度／风扇；目标百分比不是实测 RPM |
| 灯光、小屏、电源 | Toolbox 控制器与运行状态，已接入；切换以实际状态为准 | 状态、设置及受限控制 | 本地受限控制 | 原有按功能授权的工具；不借此管理 MCP 自身 |
| 历史与今日／本月流量 | Monitoring 差值及持久历史，已接入；不足一个有效差值为未知 | 图表、流量统计 | 固定指标趋势 | 概览快照含有限状态；没有独立通用历史查询工具 |
| Docker 容器资源及端口 | 固定本机 Docker 查询，已接入；资源不可读为未知 | 列表、详情及受限启停 | 容器列表、详情及受限启停 | 状态容器；已登记项目另有三个只读工具 |
| 原厂应用／下载／媒体状态 | 应用和媒体只用显式刷新后的脱敏快照；下载为受限 aria2／qB 查询，**来源未验须逐引擎核对** | 原厂业务模块展示逐项来源、时间和失败 | 当前应用页只接容器，**原厂业务未接入展示** | `apps` 读取应用缓存；媒体工具显式采集；**无独立下载队列工具** |

| 端口对应进程、实体盘位／池映射、DIMM | 监听 inode 已采集但未做 PID 关联；盘位和内存条没有已核验映射，**可填但未接入／来源未验** | 端口 PID、进程关联和盘位未知；DIMM 列表不造数据 | 监听与容器映射，不扩展未验证信息 | 同状态模型，不提供任意进程／硬件查询 |
| GPU、功耗、能耗、电压 | GPU 仅驱动实际提供的 sysfs 字段；功耗仅 CPU 封装 RAPL；整机功耗、DIMM、电压和能耗没有可靠来源 | 不显示 GPU／功耗／能耗卡；**本轮将硬盘功耗、活动盘数和估算参数的兼容零值改为 `null`** | 不增加缺来源卡片 | RAPL 可保留；整机及硬盘估算不作为观测值 |
| 文件与 Docker 完整业务 | 文件根仅元数据；三个固定项目读取有执行器，其余十六项合同**未实现** | 所有者查定义、登记项目不等于已经部署或可读文件 | 未接入文件业务 | 四项合同已有实现且需逐项授权，其余不注册假工具；ACL／安全打开仍需证据 |
| 原厂安装、下载控制、影视／相册管理、分享与备份 | 固件静态路由是线索，**对应机器执行器未实现** | 业务状态不等于业务管理 | 未接入 | 无对应工具，不能由预授权或管理员角色推定可用 |

完整 SN 是用户本次“网页填 SN”要求新增的所有者网页投影，不扩展公开监控、小屏或机器 Token 的身份权限。有口令时需所有者网页会话；无口令时沿用产品公开面板授权；开发者白名单自身和 Bearer Token 均不能取得该投影。显式开发 `storage_identity` 保留原有授权用途。

`storage_identity_cached()` 只读取有界现有元数据并复核设备生命周期，不调用原厂 RPC、不启动 SMART、不访问块设备，不调用 `space_manage`。后台从固定列表得到的证据缺失、序列号／端口重复、身份冲突或换盘都返回 `null`，不会从原厂单边记录猜 SN。SMART 原始详情改为健康与计数字段的白名单投影；只有同次核验通过的 SN 能回填到所有者详情，避免原始身份字段绕过冲突判定。

部署后需在实际 NAS 核对四盘缓存的 SN 与当前物理盘一致、休眠盘不因打开网页唤醒、换盘／冲突返回未知，并检查未登录、默认 v1、MCP、开发白名单的边界。应用／媒体需所有者显式刷新，下载需逐引擎证明本机监听归属与认证结果；失败原因或缺证据不能写成“无任务”。文件与固定项目的后续门槛见[只读验收](file-docker-readonly-acceptance.md)，业务来源见[业务诊断](business-diagnostics.md)。
