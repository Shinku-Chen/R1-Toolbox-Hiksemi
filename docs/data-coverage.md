完整 SN 是用户本次“网页填 SN”要求新增的所有者网页投影，不扩展公开监控、小屏或机器 Token 的身份权限。有口令时需所有者网页会话；无口令时沿用产品公开面板授权；开发者白名单自身和 Bearer Token 均不能取得该投影。显式开发 `storage_identity` 保留原有授权用途。

`storage_identity_cached()` 只读取有界现有元数据并复核设备生命周期，不调用原厂 RPC、不启动 SMART、不访问块设备，不调用 `space_manage`。后台从固定列表得到的证据缺失、序列号／端口重复、身份冲突或换盘都返回 `null`，不会从原厂单边记录猜 SN。SMART 原始详情改为健康与计数字段的白名单投影；只有同次核验通过的 SN 能回填到所有者详情，避免原始身份字段绕过冲突判定。

部署后需在实际 NAS 核对四盘缓存的 SN 与当前物理盘一致、休眠盘不因打开网页唤醒、换盘／冲突返回未知，并检查未登录、默认 v1、MCP、开发白名单的边界。应用／媒体需所有者显式刷新，下载需逐引擎证明本机监听归属与认证结果；失败原因或缺证据不能写成“无任务”。文件与固定项目的后续门槛见[只读验收](file-docker-readonly-acceptance.md)，业务来源见[业务诊断](business-diagnostics.md)。

当前全量 MCP 七十五项，按 Token 精确授权过滤；存储 v5 不使旧 policy v1／v2 扩权，旧 v4 只读不改字节。下载和 Docker 属于独立原生引擎委托，不能宣传整体受 Users 文件沙箱约束。`file_protocol` 仅显式检查；独立 `/api/dev/native` 的 `probe/packages` 须确认，包形状不等于可信安装。默认开发仍仅四项。当前源与剩余验收条件详见[完成矩阵](mcp-completion-matrix.md)。
