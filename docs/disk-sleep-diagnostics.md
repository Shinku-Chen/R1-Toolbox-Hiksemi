# 磁盘空闲与休眠排查

## 原厂规则与当前限制

对应 Build_260907 的 `temp_control` SHA-256 为 `745cd85d96fdcd1655455c652850abc49290dba5326b7f93ef2c5710e0de1719`。静态确认 `disk_autosleep@0xf2d7` 在 `0xf379–0xf37f` 判断每端口空闲分钟数大于 29，即达到 30 分钟才具备待机资格；循环在 `0xf770–0xf778` 设定下一轮约 60 秒后检查，因此不承诺恰好第 1800 秒机械停转。

`disk_get_interval@0x22f42` 在 `0x231c8` 起由当前时间与对应端口驱动时间戳计算分钟数。这是该执行者中的硬编码阈值，不是 Toolbox 的网页参数；当前没有找到并验证可写的原厂休眠时间配置接口，也没有实现修改原厂二进制或替代硬盘电源策略。静态证据不等于所有固件或全部系统服务共用这一规则。

时间戳通过 `/dev/hikio` 的 `0x5771` 读取，最终由内核 `hik_get_hdd_exc` 提供；内核维护和重置该时间戳的完整条件尚未确认。因此 proc 的零 I/O 不能替代原厂空闲计时器，观察到写入只能说明对应窗口存在活动，不能据此反算下一次确切休眠时间。

原厂逐盘检查，不要求全部盘共同空闲。`count@0x24120` 排除 `queue/rotational == 0` 的 SSD，剩余仍活动机械盘大于一块时，当前符合空闲条件的端口直接进入待机；最后一块才走通知与收尾。不能把 SSD 写入或另一块机械盘忙碌当成其他盘不休眠的充分理由。进程重启会重建线程状态，监督端是否反复重启也需要单独核对。

## Toolbox SMART 采集边界

2026-10-31 起，Toolbox 停止启动和后台自动 SMART 查询；网页、小屏、详情、健康与温控仅消费所有者显式刷新后的新鲜缓存，缺失或三十秒过期保持未知。普通刷新仍使用待机保护，单次强制刷新须明确确认可能唤盘，不成为持久开关；完整合同见 [SMART 按需刷新](smart-refresh.md)。这项变更尚不证明 NAS 已进入真实待机，也不能排除原厂服务、业务进程或其它数据卷写入。

下方旧镜像的观察记录保留其原日期和版本，不能将当时的 SMART 采集节奏当成新版本仍在自动执行的证据。`disk_activity` 本身继续不执行 SMART。

## 固定被动检测

在有效开发窗口且实际来源命中非空 LAN IP／CIDR 白名单时，显式请求：

```json
{"action":"snapshot","checks":["disk_activity"]}
```

入口为 `POST /api/dev/diagnostics`，同源 `Origin`、JSON、`X-FNM-Request: 1` 必需。不接受磁盘、PID、目录、命令、时长或原厂 action 参数；不需要 `R1_DEV_ALLOW_COMMANDS`，不能用 Bearer 或转发头替代开发来源。窗口在采集后失效则丢弃结果。默认四项检测不增加本项目，也不把它加入后台监控。

结果位于 `snapshot.checks.disk_activity.data.activity`：

- `disks`：物理整盘累计读写字节、操作次数、可用时的 discard／flush 次数和在途请求；不把分区再累加一次。`delta` 为与同一服务上次显式采样的差值，未知为 `null`。
- `processes`：最多 32 项的进程名、PID、启动时刻、累计与增量 `read_bytes/write_bytes/cancelled_write_bytes`，按本窗口读写增量排序；省略数量、不可读和中途换代分别报告。它是进程总体记账，包含相关子进程记账的内核语义，不能映射为某块盘的精确归因。
- `history_storage`：只用当前进程的挂载表匹配内部已知历史目录，返回设备号、受限设备名与文件系统，不访问该目录，不导出卷绝对路径或用户文件名；歧义为未核验。
- `toolbox_history`：已有历史设置、真实记录状态和最近写入时间。历史开启时每 30 秒向原独立数据卷写入；若该卷在机械盘上可能阻止空闲。采样不会为诊断创建、修复或访问历史数据库。
- `complete/partial_reasons`：逐项报告权限不足、解析失败、扫描上限或时间上限；不以缺测填零。进程扫描最多 4096 项、额外时间预算 3 秒，单个 proc 文本有界读取。

首次采样为 `baseline`。建议相隔至少五秒再次采样，只有间隔大于零且不超过 300 秒、同次启动、同设备生命周期／进程启动身份、计数未回退时返回增量；重启、换盘、PID 复用、时钟回退和超窗重新基线。采样不等待休眠窗口，也不自动重试。原始累计值始终带观察语义，不证明机械转动或当前功率；`power_state` 保持 `null`，零 I/O 也不冒充休眠。

采集只打开受限 proc/sys 元数据，不打开块设备，不读取用户文件、FD 目标、命令行、环境或凭据，不执行 SMART、`hdparm`、原厂空间管理、应用／媒体刷新、下载器查询或停用服务。Linux 计数含义依据[内核 I/O 统计](https://www.kernel.org/doc/html/v5.15/admin-guide/iostats.html)和[进程 I/O 记账](https://cdn.kernel.org/doc/html/latest/filesystems/proc.html)。

## 2026-10-30 实机观察

NAS 为 `sha-e54efa9e852f6b209e7a6825ac2dcc52b895c5b5`。北京时间 00:12:43 至 00:15:42，通过原有 `GET /api/overview` 读取缓存共 85 次，观察约 179 秒；没有修改休眠设置、风扇、下载任务或原厂服务。该旧镜像尚无新增的 `disk_activity`，因此本轮不能按进程定位每盘写入。

| 设备／自定义名称 | 有写入的采样数 | 观察结果 |
|---|---:|---|
| `sda`／备份磁盘 | 16／85 | 反复有写入，未达到持续无 I/O |
| `sdb`／视频资源 | 41／85 | 反复有写入，未达到持续无 I/O |
| `sdc`／主磁盘 | 27／85 | 反复有写入，另有一次读取样本 |
| `sdd`／SSD | 77／85 | 持续业务写入，不按机械盘判断 |

历史记录开启，数据卷实际位于 SSD 的 Users 目录，因此不能把 Toolbox 每三十秒的历史写入认作本轮三块机械盘写入的原因。下载缓存同时报告 qB 有两个下载及一个上传任务，这是排查线索，不能据此把三块盘的全部写入都归给 qB。要区分下载、索引、日志、文件服务或其他活动，需要新增诊断的进程增量与相应业务证据；CPU 占用和进程存在不能代替 I/O 归因。

此观察窗口不足 30 分钟，不能宣称已完整复现休眠故障；目前能确定的是观察期间存在真实反复写入，没有达到原厂所需的连续空闲条件。后续可在用户正常停止业务后比较被动计数，验证至少一个完整原厂窗口，但不会为排查自动暂停任务、卸载磁盘或强制待机。
