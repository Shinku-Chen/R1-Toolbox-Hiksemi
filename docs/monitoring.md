# 监控、趋势与本地健康记录

网页打开即显示监控；解锁设置后才可更改阈值或控制设备。小屏保留大字重点信息与分级详情，复杂图表和参数适合在电脑或手机网页查看。读取接口与五位配对方式见 [公开 API](public-api.md)。

本服务独立实现，消费现有只读采集结果、`/proc/diskstats` 和可读 RAPL 计数器。不会执行附件程序，不进行网络探测，不启动 SMART 自检，不为生成报告唤醒硬盘，也不会根据 CPU 使用率虚构整机功耗。

## 指标与来源

| 指标 ID | 单位 | 来源与缺测边界 |
|---|---|---|
| `cpu_usage_percent` | % | 已有 CPU 时间差分；来源过期不沿用旧值 |
| `memory_usage_percent` | % | 已有 `/proc/meminfo` 占用 |
| `rx_bytes_per_sec` / `tx_bytes_per_sec` | B/s | 已计网口的真实差分速率；首次差分、缺测为 `null` |
| `cpu_temperature_c` | °C | 当前有效 CPU 测点中的原始最高温 |
| `disk_temperature_c` | °C | 当前生命周期有效且三十秒内的合法 SMART 缓存最高温；不读取磁盘 hwmon |
| `temperature.<source-id>` | °C | 保留独立 CPU／主板／硬盘来源，标签由来源提供 |
| `cpu_package_w` | W | RAPL 的 package 能量计数差分；只有具备可读来源并形成有效差分才出现 |
| `disk_read_bytes_per_sec` / `disk_write_bytes_per_sec` | B/s | 基础块设备计数差分；内核 sector 统一按 512 字节，排除分区、md、dm 重复累加 |
| `fan_rpm.<id-hash>` | rpm | 有效设备库存中的真实 `fanN_input`；保留驱动／通道标签，0 与未知不同 |
| `fan_cpu_target_percent` / `fan_system_target_percent` | % | 独立风扇控制器当前有效的**请求输出**，并非 RPM 或实际 PWM 读回 |

所有数值保留 `0` 与 `null` 的区别；合法负温度不会变成缺测。CPU／主板温度使用各来源自身的有效期，监控只读三十秒有效 SMART 缓存，采集仅由所有者手动、Web 磁盘视图进入刷新、概览／小屏缺测补齐或有效风扇硬盘需求触发，缺失／过期为未知。GET 和缓存读取不延长读数寿命，只有新采集才有新时间。其它设备库存低频采集，RPM 会在库存过期或采集失败后消失。

磁盘挂载容量也不随两秒监控周期测量。基本状态和网页只投影当前挂载／设备代次仍匹配的容量内存快照，冷启动无快照时 total／used／usage 保持 null；物理盘字节数仍取内核 size。`capacity_sampled_at` 是原测量时间，不随状态时间戳更新，`capacity_source` 保留兼容标识 `manual_statvfs_cache`，也包括按需快照，身份变化即拒旧，不持久化。所有者显式容量刷新会访问文件系统元数据并可能唤盘，独立合同见 [容量按需刷新](capacity-refresh.md)。

RAPL 只合计可读的 CPU package 域，排除 core／uncore 等子域重复计算。首次采样、过长间隔、范围变化或计数异常均不生成瓦数；能量计数正常回绕可形成差分。没有 RAPL 就隐藏对应图表，不使用 TDP、CPU 占用或“基础功耗”估算替代。它不等于整机插座功率，因此不提供据此推导的整机电费或能耗账单。

监控不改变风扇选源或控温规则。页面中的最高温汇总只是显示指标；独立风扇控制仍按各自已应用规则运行。

## 历史与写盘

`monitoring.json` 保存设置；`monitoring.sqlite3` 保存趋势、流量基线、本地告警事件与 SMART 观测。它们位于现有独立 Docker 数据卷，和原厂 AppImage、`dist`、启动脚本分开。复用原数据卷才能在镜像升级或重新创建项目后继续读取记录。

后台约每 2 秒更新实时缓存，约每 30 秒把最新快照与累计增量批量写入 SQLite。HTTP 读取只取内存缓存；网页拖动图表或频繁请求不会直接发起数据库查询。数据卷写入、SQLite 错误与历史查询不会占用实时读取锁执行慢 I/O。

**启用历史会增加数据卷写入，并可能影响该卷所在硬盘休眠。** 应尽量把卷放在已有活动的配置存储或 SSD 上；不能承诺“监控开启后数据盘一定休眠”。关闭历史后不再持续写入趋势／流量／事件，实时指标和本次进程中的累计仍可用，但这些内存数据不保证跨重启保存；旧历史文件不会被自动删除，也不会冒充关闭后仍有完整 30 天数据。显式修改设置仍需写入设置文件。

| 边界 | 本版限制 |
|---|---|
| 保留天数 | 可设 1–30 天；从实际开始记录算起，不补过去的数据 |
| 样本条数 | 最多 86,400 条，通常对应 30 秒采样的 30 天 |
| 数据库大小 | 最多 32,768 个 4 KiB 页面，约 128 MiB；接近容量时淘汰较早样本，因此不保证始终留足 30 天 |
| 单个样本 | 最多 64 个指标；独立来源有界，不无限枚举 |
| 对外趋势 | 每个系列最多 720 点；较长范围按时间桶取最后一个样本，不宣称保留桶内全部峰值 |
| 本地记录 | 数据库最多 2,000 个告警事件与 1,000 个 SMART 观测；读取默认各取最近 100 条 |

时间范围为 `10m`、`1h`、`6h`、`24h`、`7d`、`30d`。历史点为 `[Unix秒, 数值或null]`。缺失指标与明显采样中断使用 `null` 断开曲线，不补成零，不用线条连接关机期间的未知状态。刚开始记录时，范围标签“30 天”只代表查询窗口，不代表已有 30 天记录；响应同时给出实际首末时间与记录状态。

宿主 Python 没有 `_sqlite3` 时，实时监控继续运行，历史明确返回不可用原因。卷不可写、数据库损坏或写入未确认时，也保留实时指标并报告异常；后台以低频尝试恢复。恢复成功后才重新标注正在记录。损坏数据库不会被自动删除或悄悄覆盖；应先保留文件再处理卷或数据库问题。异常关机可能丢失尚未批量写入的最后一段数据。

## 今日／本月流量

累计来自每接口接收／发送的真实字节计数差值，单位 B。保存的基线包含系统 boot ID；只有启动身份一致、计数不回退、时间顺序有效才计入差值。没有首次基线、NAS 重启、计数重置或缺测时不产生负值、巨大跳变或估计流量。服务在同一次 NAS 启动中重建，且基线与当前仍在同一统计周期时，可以继续累加两端计数器实际形成的差值。

日期按宿主本地时区划分。跨午夜的缺口不能准确分配给两天，因此不计入新一天；如果仍在同月，真实差值可计入当月。跨月缺口同样不估计分摊。`partial: true` 与 `coverage: observed_counter_deltas` 表示只有实际覆盖的计数增量，不能称完整运营商账单。

默认排除可识别的虚拟／上层网口：名称规则与只读 sysfs 拓扑识别 bridge、bond、team、VLAN、veth 等，避免把聚合接口和物理成员重复相加。无拓扑证据的接口不会凭名称以外的信息猜测归属。关闭“排除虚拟接口”后会按所列接口计数，聚合总计可能重复。多个真实网口之和是这些接口各自实际经过的字节数，不能当成去重后的互联网下载量；容器级流量也不从网口总量倒推。

## 告警与 SMART 观测

可设置 CPU／内存／数据盘占用、CPU 最高温、硬盘最高温的警告与严重阈值。每组必须满足“警告 < 严重”，百分比范围 1–100；CPU 温度阈值范围 10–110°C，硬盘为 10–90°C。它们是监控提示阈值，**不会修改独立风扇的 80°C 等保护条件**。

默认阈值：CPU／内存／空间占用为 85%／95%，CPU 温度为 70°C／80°C，硬盘为 50°C／60°C。达到阈值、严重级别改变和有有效新读数确认恢复时，会记录本地事件。已经告警的来源随后丢失或过期，会保留明确 `stale` 状态，不把“读不到”记录为恢复。

SMART 摘要只消费仍新鲜的合法缓存，不因健康评估触发 `smartctl`。Web 磁盘视图进入刷新、概览／小屏缺测补齐和有效风扇所选硬盘取温有独立受限授权，不是健康评估的默认采集。明确休眠、无有效 SMART 或测量缓存三十秒过期均保持未知；不会为了更新健康记录运行采集、自检或扫描。所有者普通／单次强制刷新的副作用边界见 [SMART 按需刷新](smart-refresh.md)。记录名为“缓存 SMART 观测”，不是长短自检通过证明，也不是介质坏道扫描结果。全局摘要只表示已采集指标当前是否触发规则，不给设备编造健康分数。

告警只存在本机，未接入 SMTP、Server酱或外部通知，也不保存这类凭据。

## 报告、导出与配置

JSON 报告包括当前允许的指标、CPU 型号／运行时长／内存总量、SMART 摘要、活动告警与流量覆盖。它不直接导出原始采集对象，不包含进程命令行、环境、口令、任意配置、设备序列号或 MAC。完整公开状态 API 的设备详情范围见 [API 说明](public-api.md)；用户应了解默认局域网公开监控的可见范围。

CSV 使用 UTC 时间与 `timestamp_utc,metric,value,unit` 长表格式。数值未知留空，文本元数据防止被电子表格当作公式。它只导出实际缓存的历史，不为缺测补点或补零。

配对后的设置动作支持部分更新，例如：

```json
{"action":"monitor.settings.update","payload":{"settings":{"retention_days":7}}}
```

允许的设置键为 `history_enabled`、`retention_days`、`traffic_exclude_virtual` 与 `thresholds`；阈值键为 `cpu_warn/cpu_critical`、`memory_warn/memory_critical`、`capacity_warn/capacity_critical`、`cpu_temp_warn/cpu_temp_critical`、`disk_temp_warn/disk_temp_critical`。未知字段、错误类型或无效顺序均拒绝保存。只有文件与目录同步确认后才返回 `settings_saved: true`，不能仅以“当前值看起来相同”当作保存成功。

本模块测试全部使用临时 proc／sys／数据卷和内存快照，覆盖可选 SQLite、写入故障／恢复、真实计数边界、RAPL 回绕、缺测与 0、聚合接口重复计数、告警时效、导出和并发读取隔离。通过测试不代表已在用户 NAS 上形成 30 天历史，也不代替风扇／灯光的实机效果验证。
