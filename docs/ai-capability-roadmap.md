# AI 全功能接入路线

目标：让局域网 AI 通过 Toolbox 的 MCP／REST 读取和操作海康 NAS 的文件、应用、容器、下载、影视、相册及系统能力。API 管理按只读、读写、管理员三级角色，功能域、精确工具及文件／项目范围共同授权。文档日期：2026-10-30。

Toolbox 以常驻容器监督宿主前台服务。网页承担健康、应用状态和简单控制；小屏接管与 MCP 独立可选，分别默认开启和关闭。首次访问无需网页口令，可在设置中启用；开发者模式必须配置局域网 IP／CIDR 白名单与有效窗口。MCP 使用独立访问密钥，支持编辑、停用、轮换及按功能、文件范围和可信来源授权，不能借用网页或开发者授权。

## 第一阶段：权限与能力目录

已实现 policy v3 的角色、逐域权限、精确 `tool_grants`、文件范围及 `docker_projects` 项目范围。默认只读且仅勾选状态，管理员也不能进入未选工具或资源。MCP 列表与调用、REST 操作共用权限判断。存储格式已到 v4，旧格式仅在真实写入时原子迁移；policy v1／v2 仍冻结原十工具，原 `files/docker` 预授权不自动激活新能力。所有者须明确升级并选择新工具，省略权限字段、改名、IP、有效期、启停或轮换不顺带升级。

API 管理已支持具体工具勾选、同根多子目录无损编辑和已登记 Docker 项目选择；尚未实现的写工具不能勾选。`GET /api/integration/capabilities` 返回本键实际工具、所选域、文件与项目范围，不输出绝对挂载路径。新资源读取在前后调用 `is_current()`，核对授权修订、Token 代际、服务与键状态和自然到期；失效则不披露未发送结果。具体格式、兼容和边界见 [MCP 与 API 管理](mcp-api.md)。

当前真实 MCP／REST 共三十六工具：原十项、文件根元数据、六项固定 Docker 项目工具及一项项目控制、五项业务缓存、六项下载任务和七项原厂媒体业务操作。缓存工具语义不变；显式联网、确认、幂等及管理员项目边界见[业务操作](mcp-business-operations.md)。文件与 Docker 二十项合同为七项已接入、十三项文件操作待实现；查阅[JSON 定义](api/file-docker-contracts.json)或 owner-only `/api/access/contracts` 不等于获准执行。

文件总边界固定为 `/drives/*/Users/`，根工具只投影已有身份缓存、sysfs／udev 生命周期核验与挂载元数据，标明 `metadata_only`，不列盘内目录、不打开文件或传输内容。Users 根使用新摘要，旧整盘授权不自动升级。NAS 主体、Unix 身份、原厂 ACL、路径映射与安全打开尚未闭合；`GET /api/access/file-readiness` 报告缺失证据，不能据已有根规划宣称可读取文件，更不能回退到宿主 root 读取。

固定项目由所有者通过 `/api/docker/projects` 的候选、登记、更新标签和撤销入口管理，Token 再选择具体登记 ID 的 `inspect/control/update_image`。登记不部署或启停项目。读取仍固定本机 Docker Unix GET、root `dockerd` peer 和共享八秒窗口，不读 Compose 原文。新增管理员操作逐步核验引擎、配置和容器身份；更新私有审查单服务 Compose、同仓库固定 digest 和并发版本，不输出原文、环境或真实路径。读取边界见[固定项目读取](docker-projects.md)，执行边界见[固定项目操作](docker-project-operations.md)。

外部 AI 仍须独立 Bearer，内部模块直接调用限定函数无需 Toolbox Token；两者不改变原厂自身的认证要求。开发者 `/api/dev/diagnostics` 不需要 Token，但必须命中实际 LAN IP／CIDR 非空白名单和有效开发窗口。新 `file_access_readiness/docker_project_readiness` 只显式采集，默认仍为旧四项，采集后窗口失效就丢弃结果；不由开发白名单管理 Token 或项目授权。

文件浏览／下载、上传及文件管理仍缺原厂 ACL 的生产后端；本批完成安全句柄传输基础及显式 `file_backend_context`，不注册假回调。固定项目管理员更新已有真实受限执行器，仍待专用项目实测。当前实现与自动化不代表 NAS 已通过：部署后须按[只读验收清单](file-docker-readonly-acceptance.md)核对旧键、元数据、登记与真实状态，文件与项目写入使用明确指定样本。

## 原厂能力核对

用户固件 `R1_X01_GML_STD_V6.3.3_Build_260907.zip` 包含对应处理逻辑。静态注册表见 [vendor-emhistor-interfaces.json](vendor-emhistor-interfaces.json)。数量指对应路由的注册项，不是已经验收的功能数。

| 领域 | 原厂证据 | 尚需审定 |
|---|---|---|
| 文件 | `/rest/1.0/file` 内联浏览、详情、上传、下载、新建、复制、移动、删除、改名；`/rest/1.1/file` 另有 126 项 | 方法、用户 ACL、虚拟目录、分块／Range、回收站和索引一致性 |
| Docker | 64 项，含 `create_project/get_project_compose/set_project_compose/project_deploy` | 配置规范化、端口、挂载、项目归属、进度及保护边界 |
| 应用市场 | 列表、安装、进度、卸载四项 | 包来源、版本、依赖、枚举和失败恢复 |
| 下载 | `dleng` 25 项，含任务增删、暂停继续、限速、保存路径 | 任务归属、原厂和 qB／aria2 独立鉴权、全局与单任务配置 |
| 影视墙 | `scraper` 42 项，含媒体库、扫描、匹配、字幕、收藏 | 本地 9660 插件、嵌套 sources／members 等结构和状态枚举 |
| 相册与 AI | `album` 62 项、`fcabm` 43 项 | 对象和照片归属、创建、成员、分享链路、识别配置 |
| 分享 | `share` 24 项、`openshare` 86 项，文件路由另有分享动作 | 外链、密码、有效期、云端依赖和撤销 |
| 备份同步 | `task` 18 项、`sync` 22 项 | 源目标、版本和冲突策略、计划、恢复和取消 |
| 账户与系统 | `config` 142 项、新存储 `config` 25 项，另有 `login/update` | 逐项区分普通配置与网络断联、格式化、修复、升级等操作 |

总计 35 个顶层 REST 路由、29 张动作表、902 条注册项，另有 33 个本地 IPC 命令。基础文件还有不在动作表内的分支，且存在同名跨路由、重复项、动态插件与云端服务；不能据此计算 APP 覆盖率。

已确认的部分契约：

- 文件上传有临时文件、offset／完整大小及完成重命名；下载有二进制与 Content-Range，但不能猜测输入协议。
- Docker `create_project` 读取 `name/path/compose/auto_run`，会写入并执行 Compose，不能裸转发任意配置。
- 应用安装经本地 8888 服务，解析 `apply_id/module_name/vid/module_type/source/version/paramList` 等；枚举和来源未闭环。
- 影视库创建读取 `name/language/auto_subtitle/tv_available/sources/members`，修改读取 `lid/.../del/add`；嵌套结构需核对。
- 普通相册创建的名称输入是 `album_name`，返回字段才是 `name`。
- 分享读取有效期、人数和文件／相册列表，可能依赖云端，不能只拼接本地 URL。

这些是用户固件的静态证据，没有执行厂商 ELF 或由此发起实机业务写入。已有媒体查询验证见 [media-probe.md](media-probe.md)，单项查询成功不代表完整业务通过。

## 后续阶段

1. **文件浏览、上传和下载。** 先闭合主体、ACL 与同对象安全打开，再由 MCP 管理对象与任务、专门 HTTP 二进制通道传输。使用根 ID 加相对路径，逐次核验身份、符号链接和路径竞态，保留原厂索引与回收站语义；证据不足保持不可用，不以宿主 root 直读替代。
2. **Docker 受控更新与部署。** 项目读取、管理员启停重启与受控镜像更新已接入；更新须 admin＋docker＋具体工具＋项目操作＋有效计划。不因文件范围授权就假设镜像代码受相同限制。通用新建部署继续设计，保护 Toolbox 与已有卷，不自动删卷，不使用 `down -v`。
3. **应用与下载器。** 根据已核验市场条目、来源和版本安装。下载任务区分移除任务与删除数据，区分单任务与全局目录，外部凭据留在宿主。
4. **影视、相册与分享。** 已有相册／影视库列表、普通相册创建改名、影视库改名和单分享撤销；继续补来源、成员、照片、匹配与字幕。公开分享创建还需服务端 ID 与外链契约，不能本地拼接。
5. **备份、账户与系统。** 逐功能审定与验收，保留硬件预检、确认和五秒电源取消；不提供 shell、SQL 或任意原厂 action 代理。
6. **对照当前 APP 补齐差异。** 需要当前客户端页面流程、APK 或正常调用记录，分别核对云账号、会员、手机后台备份、推送、投屏与外设。不能仅凭 NAS 固件承诺替代全部客户端和云端行为。

后续复制、部署、安装与扫描等长任务须提供任务 ID、真实进度和脱敏终态；只有后端证明确实可安全中断才开放取消。超时先核对实际状态，避免重复创建。调用记录不存内容、参数、环境变量或凭据。

## 验收

- 当前自动化覆盖角色 × 功能域 × 精确工具 × 文件／项目范围、v4 原子迁移、v1／v2 不扩权，以及短读中撤销、轮换和自然到期时丢弃结果。
- 当前 NAS 实机验收仅读取已登记项目的状态与摘要、核对根元数据和文件就绪缺口；不创建样本、不修改业务文件、不执行部署或更新。候选存在、登记成功或 HTTP 200 均不代替项目真实状态验收。
- 后续文件读写验收使用明确指定的专用目录和样本，上传／下载校验 SHA-256，核对中文名、大文件、断点、覆盖冲突、越界、换盘和 APP 可见性；当前没有宣称这些能力已通过。
- 后续 Docker 写入使用专用项目核对端口、卷、进度、幂等与部分失败恢复，不停止厂商服务或修改已有数据。
- 应用、媒体和分享按真实插件、用户与任务验收，不拿 HTTP 200、表项存在或 Mock 代替实机结果。
- 调试通过镜像内有界开发 API，不用 SSH；先收集完整现场，避免反复打包追加零散诊断字段。
