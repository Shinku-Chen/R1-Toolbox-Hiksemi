# AI 全功能接入路线

目标：让局域网 AI 通过 Toolbox 的 MCP／REST 读取和操作海康 NAS 的文件、应用、容器、下载、影视、相册及系统能力。API 管理按只读、读写、管理员三级角色，功能域、精确工具及文件／项目范围共同授权。文档日期：2026-10-30。

Toolbox 以常驻容器监督宿主前台服务。网页承担健康、应用状态和简单控制；小屏接管与 MCP 独立可选，分别默认开启和关闭。首次访问无需网页口令，可在设置中启用；开发者模式必须配置局域网 IP／CIDR 白名单与有效窗口。MCP 使用独立访问密钥，支持编辑、停用、轮换及按功能、文件范围和可信来源授权，不能借用网页或开发者授权。

## 第一阶段：权限与能力目录

已实现 policy v3 的角色、功能域、精确工具、文件子目录、Docker 项目／未来部署及应用安装对象 application_ids。存储 v6 读旧不改字节、真实写原子迁移；旧安装键仅 ID34，新键默认空，不自动扩权。

API 管理已支持具体工具、同根多子目录、已有项目和未来资源分别授权；Token 操作页能显式查询并登记固定部署资源、撤销和重核生命周期，不代理机器部署。Docker 域可只选现有项目或未来资源一类。`GET /api/integration/capabilities` 只返回本键真实权限，不输出绝对挂载路径。新资源读取前后及文件每块发送前后续验当前授权，关闭／撤权后不披露未发送结果。见[MCP 与 API 管理](mcp-api.md)。

当前八十一工具，文件／Docker 二十一项合同均有实际适配。覆盖、目录、复制、改名、移动与真实原厂回收已接；仍须真实 ACL、FD、恢复区及独立索引门槛，注册不代表 NAS 验收通过。见[文件变更](file-mutations.md)。

文件总边界固定 `/drives/*/Users/`，根工具继续只投影元数据，旧整盘授权不换根。新文件执行器严格核验精确固件、固定原厂所有者、完整原厂逻辑 ACL 的 `admin/public` 正子集、同挂载拓扑和最终只读句柄；其他用户读取不开放，不把逻辑 ID 当 Unix UID。浏览、属性、下载准备／状态／取消已有实际回调与字节通道。`364b858` 已完成三个实际根的 admin 浏览，下载内容仍待指定样本；本批修复规范 /drives 之外完整别名误排唯一规范 Users 根的问题，不把别名注册成新根，堆叠和 Users 内嵌挂载仍拒绝。新增上传三工具仅限已核验内置 SATA 的 admin 后代新文件，准备／PUT／提交／独立原厂索引确认分开；必须同时具备真实写 ACL、父目录授权、容量保留和同对象无覆盖发布，未实机写验收，不把临时句柄或通知 ACK 当完成。见[真实只读后端](native-file-readonly.md)和[上传通道](file-upload-transport.md)。

固定项目由所有者通过 `/api/docker/projects` 的候选、登记、更新标签和撤销入口管理，Token 再选择具体登记 ID 的 `inspect/control/update_image`。登记不部署或启停项目。读取仍固定本机 Docker Unix GET、root `dockerd` peer 和共享八秒窗口，不读 Compose 原文。新增管理员操作逐步核验引擎、配置和容器身份；更新私有审查单服务 Compose、同仓库固定 digest 和并发版本，不输出原文、环境或真实路径。读取边界见[固定项目读取](docker-projects.md)，执行边界见[固定项目操作](docker-project-operations.md)。

独立未来部署已支持新建、同仓库 digest 更新、启停重启和停止后删除；所有者先登记具体已有卷／网络、固定仓库／端口／用户／配额，再由管理员精确获权后规划／执行。保护 Toolbox 和数据卷，不执行任意 Compose、不删卷，故障保留现场。见[受控新服务部署](docker-deployments.md)。

外部 AI 始终使用独立 Bearer；内部限定函数调用不改变原厂认证。开发目录现有十项，默认仍仅 `device/storage/business/fan`。`file_protocol` 等只能显式选择；独立 `/api/dev/native` 严格 `probe|packages`＋`confirm:true`，前者固定六类查询，后者只取应用包字段形状，均不安装或执行 setter，且可能唤盘／初始化原厂状态。开发白名单不能管理自己、Token 或资源授权。新增工具仍需新镜像部署、固定诊断和指定样本逐项验收。

## 原厂能力核对

用户固件 `R1_X01_GML_STD_V6.3.3_Build_260907.zip` 包含对应处理逻辑。静态注册表见 [vendor-emhistor-interfaces.json](vendor-emhistor-interfaces.json)。数量指对应路由的注册项，不是已经验收的功能数。

| 文件 | `/rest/1.0/file` 内联浏览、详情、上传、下载、新建、复制、移动、删除、改名；`/rest/1.1/file` 另有 126 项 | 方法、用户 ACL、虚拟目录、分块／Range、回收站和索引一致性 |
| Docker | 64 项，含 `create_project/get_project_compose/set_project_compose/project_deploy` | 配置规范化、端口、挂载、项目归属、进度及保护边界 |

总计 35 个顶层 REST 路由、29 张动作表、902 条注册项，另有 33 个本地 IPC 命令。基础文件还有不在动作表内的分支，且存在同名跨路由、重复项、动态插件与云端服务；不能据此计算 APP 覆盖率。

已确认的部分契约：

- 文件上传有临时文件、offset／完整大小及完成重命名；下载有二进制与 Content-Range，但不能猜测输入协议。
- Docker `create_project` 读取 `name/path/compose/auto_run`，会写入并执行 Compose，不能裸转发任意配置。
- 应用安装只新装审计 ID7／8／34／35，另须 application_ids 精确授权，双实时目录与当前计划；预览不安装，原厂受理不等于完成。更新、卸载、其他／核心模块和任意包输入不开放。
- 影视库创建读取 `name/language/auto_subtitle/tv_available/sources/members`，修改读取 `lid/.../del/add`；嵌套结构需核对。
- 普通相册创建的名称输入是 `album_name`，返回字段才是 `name`。
- 分享读取有效期、人数和文件／相册列表，可能依赖云端，不能只拼接本地 URL。

这些是用户固件的静态证据，没有执行厂商 ELF 或由此发起实机业务写入。已有媒体查询验证见 [media-probe.md](media-probe.md)，单项查询成功不代表完整业务通过。

## 后续阶段

1. **文件读写实机验收。** 六类变更已有适配，先通过显式 owner 预检核对实际权限／恢复区，再使用独立测试对象核对上传、覆盖、目录、复制、改名、移动、真实原厂回收与恢复；用户原始样本只读。其他用户和递归目录仍需独立证据。
2. **Docker 实机与更多结构。** 已有项目和受控新服务均有执行器；用专用服务核对固定资源、健康、生命周期、幂等及故障保留。任意 Compose、bind、设备、特权或多服务拓扑仍不开放，不能声称镜像代码受 Users 文件沙箱限制。
3. **应用与下载器。** 已有目录、带副作用的安装进度、包诊断及 ID34/netdisk_bd2 白名单新增安装；管理员计划只核对当前目录，执行另须当前计划版本、确认和本键幂等。安装可能联网、写原厂程序目录并启动后台进程，ACK 仅受理，不明结果不重放；真实新装尚未验收，更新／卸载及其他应用仍需逐项证明来源、依赖和清理边界。下载十二工具已有；创建链接／种子、改目标与删除数据仍需文件权限和真实引擎契约。
4. **影视、相册与分享。** 已有影视扫描状态、普通相册删除及原七工具；继续核对来源、成员、照片、播放、匹配与字幕。分享创建需服务端 ID、外链、密码及有效期合同，不能本地拼接。
5. **备份、账户与系统。** 已有备份目录／设置、关闭自动导入、暂停／取消既有任务、最小用户目录、设备名和 AI 开关；创建／恢复备份、账号权限与凭据、网络／存储变更和升级仍需各自契约。保留五秒电源取消及硬件门槛，不开放任意 action 代理。
6. **对照当前 APP 补齐差异。** 需要当前客户端页面流程、APK 或正常调用记录，分别核对云账号、会员、手机后台备份、推送、投屏与外设。不能仅凭 NAS 固件承诺替代全部客户端和云端行为。

后续复制、部署、安装与扫描等长任务应返回后端实际提供的任务 ID、真实进度和脱敏终态；没有原厂任务 ID 时保持 null，不编造标识或完成率；只有后端证明确实可安全中断才开放取消。超时先核对实际状态，避免重复创建。调用记录不存内容、参数、环境变量或凭据。

## 验收

- 自动化覆盖角色、域、精确工具、文件／项目／部署／应用对象，v6 原子迁移、旧字节不改、旧键不扩权；内容传输及权限快照在撤权／轮换／到期后丢弃未发送结果。文件变更另有真实 Linux root 句柄、竞态、恢复及固定原厂数据库测试。
- 当前 NAS 实机证据包括三个 admin 目录浏览、部分目录属性、业务及监控缓存；固定 Docker 项目尚未登记核对，不创建样本、不修改业务文件、不执行部署或更新。候选存在、登记成功或 HTTP 200 均不代替项目真实状态验收。
- 后续文件读写验收使用明确指定的专用目录和样本，上传／下载校验 SHA-256，核对中文名、大文件、下载单 Range、上传会话不可重放、同名拒绝、越界、换盘和 APP 可见性；当前没有宣称这些能力已通过。
- 后续 Docker 写入使用专用项目核对端口、卷、进度、幂等与部分失败恢复，不停止厂商服务或修改已有数据。
- 应用、媒体和分享按真实插件、用户与任务验收，不拿 HTTP 200、表项存在或 Mock 代替实机结果。
- 调试通过镜像内有界开发 API，不用 SSH；先收集完整现场，避免反复打包追加零散诊断字段。
