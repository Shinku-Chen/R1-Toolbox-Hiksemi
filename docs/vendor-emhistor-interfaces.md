# 原厂 emhistor 静态接口清单

本页分析海康 R1 `V6.3.3 Build_260907` 的 `/histor/bin/emhistor`，复核日期为 2026-10-29。只读取用户提供的固件字节，不执行厂商程序、脚本或接口，不访问 NAS。动态模块、其他原厂进程和云端接口不包含在本清单内。

完整机器可读条目见 [vendor-emhistor-interfaces.json](vendor-emhistor-interfaces.json)。清单包含动作原文、处理函数地址、表项虚拟地址、文件偏移和实际分发函数的交叉引用，便于后续逐项复核。

## 覆盖范围和证据

| 已完整枚举的静态表 | 数量 | 表位置与分发证据 |
|---|---:|---|
| 本机 IPC 命令 | 33 | 表 `0x112f2c0`；分发函数 `0x10eee6`，引用点 `0x10f117` |
| 顶层 REST 路由 | 35 | 表 `0x112fee0`；分发函数 `0x174ec6`，引用点 `0x175ccb` |
| 与路由相连的 REST 动作表 | 29 | 逐表保留分发函数和引用点 |

枚举依据是实际的“名称指针／处理函数指针”表、零处理函数终止项和分发函数中的 RIP 相对引用，不把字符串扫描结果直接当成可调用接口。Unicode 属性表、SQLite 系统调用表、模块内部回调等同样可能包含名称和函数指针，已排除。

以下 6 个顶层路由未关联到本次枚举的 29 张动作表：`/rest/1.0/quota`、`/rest/1.0/file`、`/rest/1.0/config`、`/rest/1.0/event`、`/rest/1.1/quota`、`/rest/1.2/quota`。它们的路由和处理函数已保留，但旧版内联分支动作不算在 902 项内。因此“静态注册表枚举完整”不等于“所有可达行为已经审计完整”。

## 设备自定义名称

已经确认的被动数据来源为：

```text
/tmp/nand_config/config.txt
  └─ dev_info
       └─ dev_name
```

`json_conf_get_dev_name` 是导出符号，地址为 `0x936200`。它在 `0x936217` 指定 `dev_info`，调用 `json_conf_load`（`0x9341ef`），再在 `0x93627f` 指定 `dev_name` 并提取字符串。既有配置加载链对应类型 0 的默认配置路径 `/tmp/nand_config/config.txt`。

原厂 REST 中也有对应入口：

| 内容 | 静态证据 |
|---|---|
| 路由 | `/rest/1.1/login` |
| `action` | `get_dev_name` |
| 动作表项 | 虚拟地址 `0x1132610`，文件偏移 `0xf32610` |
| 处理函数 | `rest_get_dev_name`，`0x27fc71` |
| 配置来源 | `dev_info.dev_name` |
| REST 返回字段 | `name`；同时构造 `product_model`、`serial_number` 等其他字段 |

当前监听地址、HTTP 方法、完整认证链及整个 REST handler 的副作用未全部验证，不应直接把这条 REST 路由加入无人值守轮询。Toolbox 使用更窄的固定配置投影即可获得同一个名称，不需要拿到或暴露原厂 `access_token`。

独立实现位于 `runtime/vendor_device.py`，函数为 `collect_vendor_device_name(root="/")`，结果只有 `available`、`name`、`source`、`reason`。`root` 仅用于内部测试注入，不能来自 HTTP 参数。

- 文件上限为 1 MiB，名称上限为 63 个 UTF-8 字节，与已验证的 `0x40` 字节 getter 缓冲一致。
- 只读普通文件，拒绝符号链接或 Windows reparse 路径；Linux 使用 `O_NOFOLLOW`、`O_NONBLOCK`，对比读取前后的文件身份和修改时间。
- 严格解析 JSON，拒绝重复键、非标准常量、无效 UTF-8、控制字符和空名称。
- 只返回 `dev_info.dev_name`，不返回原始配置、设备序列号、用户账号或异常路径；不以 hostname、型号或默认设备名填补。
- 文件缺失或读取期间变化时返回未知；不创建、修复或改写原厂配置，不执行厂商命令。

这个名称是整台 NAS 的自定义名称。硬盘当前空间名称属于存储服务的另一条接口链，不能由 `get_dev_name` 或 hostname 推导。

## 可接入功能分类

下表是静态入口的用途分组和接入顺序，**不是自动调用授权或只读安全结论**。每一个动作的原文见 JSON 清单。

| 功能组 | 主要 REST 路由 | Toolbox 接入建议 |
|---|---|---|
| 设备身份、用户与权限 | `/rest/1.1/login` | 优先采用设备名称等固定字段的被动投影；用户、口令、会话数据不向公开监控接口透出 |
| 硬件、系统与存储策略 | `/rest/1.1/config`、`/rest/1.2/config` | 可作为灯效、原厂系统风扇、屏幕、电源、存储状态的证据入口；逐项核实参数、确认门槛、真实效果和回退 |
| 任务和通知 | `/rest/1.1/task`、`/rest/1.1/message` | 先审计状态读取；删除消息、任务取消或状态推进需要单独授权 |
| 容器 | `/rest/1.1/docker` | 可研究原厂容器状态；保留现有 Docker 查询路径。创建、启动、停止、删除、迁移和镜像操作不自动调用 |
| 软件与更新 | `/rest/1.1/update`、`/rest/1.1/applycenter` | 先研究版本和安装状态；升级、安装、卸载不作为监控轮询 |
| 本地文件、同步与分享 | `/rest/1.1/file`、`/rest/1.1/sync`、`/rest/1.1/share`、`/rest/1.1/openshare` | 属于用户数据业务，可能产生磁盘读取、索引或写入；不因动作以 `get_` 开头就用于硬件后台采集 |
| 相册、人脸、媒体与刮削 | `/rest/1.1/album`、`/rest/1.1/fcabm`、`/rest/1.1/scraper` | 文件和个人数据范围，需要独立业务需求、权限及休眠盘影响审计 |
| 摄像机与视频接入 | `/rest/1.1/plug` | 可研究已接设备状态；发现、关联、配置及账号字段不自动暴露 |
| HDMI、DLNA 与打印 | `/rest/1.0/hdmi`、`/rest/1.0/dlna`、`/rest/1.1/yprint` | 属于可选业务集成；播放、音量、广播和打印本身会改变状态 |
| 下载与云盘 | `/rest/1.1/thunder`、`/rest/1.1/dleng`、`/rest/1.0/bdpan`、`/rest/1.1/bdpan`、`/rest/1.1/ydpan` | 可研究任务状态；涉及云账号、令牌、下载、上传和同步，不作为公开硬件能力 |
| 调试、代理与扩展服务 | `/rest/1.1/debug`、`/rest/1.1/proxy`、`/rest/1.1/openclaw`、`/rest/1.1/jdxb`、`/rest/1.1/openinfo` | 默认仅留静态清单；需确认认证边界、实现和当前组件安装情况，不开放任意转发或命令桥 |

原厂本机 IPC 的 33 项包含时间、连接数、磁盘列表、设备信息、摄像机、灯效通知、风扇、热插拔等功能。它们共享 `/var/tmp/emhistor`，参数结构仍需逐项复核。当前已验证的风扇客户端使用 `emhistor;<command>;<parameter>` 加 NUL，并按原厂要求建立权限为 `0700` 的具名客户端 socket；不能把这一帧的第三段含义推广到所有命令。

特别注意：`get_fan_status` 虽然以 `get_` 开头，但会同步原厂温控信号，缺配置时还可能初始化默认值。本清单将它和已验证的 `set_fan_status` 标成 `changes_state`，其他未逐项审计的动作统一标 `unknown`。`suggested_use` 中按名称识别的写入意图仅用于审计排序，不是处理函数完整语义的替代品。

## 验证边界

这份清单证明样本存在对应注册表和回调，不证明当前 NAS 正在监听某个端口、组件已安装、用户权限满足，或实际固件与样本完全相同。新增适配必须先核验当前设备的版本和受限响应，使用既有后台缓存，不通过打开网页临时探测硬盘、执行 SMART 自检或唤醒休眠盘。

后续逐项接入时应保留数据来源、只读等级、参数约束、字段上限、缺失原因和已有真实授权流程。未核实的测量维持 `null`／`--`，不把配置目标冒充实测数据。
