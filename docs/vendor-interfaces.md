# 原厂接口与 Toolbox 接入范围

基于用户提供的 `V6.3.3_Build_260907` 固件，2026-10-29 静态复核。固件中的接口不等于当前 NAS 已监听、已授权或适合后台轮询；查询动作也可能写配置、发信号或唤醒硬盘。

## 本轮已接入的名称读取

| 信息 | 原厂来源 | Toolbox 处理 |
|---|---|---|
| 设备自定义昵称 | `dev_info.dev_name`；原厂 REST 也有 `/rest/1.1/login` 的 `get_dev_name` 动作 | 固定只读配置投影，仅返回名称；与 Linux `hostname` 分开 |
| 磁盘／空间自定义名称 | `/var/tmp/disk` 的 `get_space_list;` | 从原厂当前内存列表取名称，单盘与 RAID 名称区分 |
| 当前物理盘关联 | 同一 socket 的 `get_disk_list;` | 成员 `disk_id` 对物理盘 `disk_serial`，`root_name` 对整盘 `disk_name`，同时核对端口，再严格匹配已有 SMART 缓存；成员 `disk_name` 实为分区名 |

详细协议、热换盘与休眠缓存规则、固定私有诊断接口和实机验收步骤见 [存储名称](disk-names.md)。实现和测试已覆盖固定读取路径；实机名称须以新镜像部署后的诊断为准，不将用户提供的名称硬编码成返回值。

## 其他能力如何接入

| 功能 | 判断与建议 |
|---|---|
| 空间类型、成员、端口、RAID 关联及修复状态 | 优先复用本轮两个现成列表中逐项验证的字段；`get_fix_status` 也是只读缓存候选。仅从已有内存取得，不为展示打开分区 |
| RAID 同步／降级状态 | 当前 Toolbox 已有 Linux mdraid 只读采集；原厂进度 getter 需要逐项核实是否只读缓存，再决定是否补充 |
| 原厂系统风扇档位、灯效、小屏、电源 | 现有受限控制保留；原厂注册表可补充协议证据。写入必须使用专门参数约束、身份预检及已有授权流程，不能转成通用 RPC |
| 休眠设置、网络、UPS、应用状态 | 可以作为后续适配方向；区分保存配置、实际状态和可用服务，完成读取链审计与实机验证后接入 |
| 原厂容器、下载与通知任务状态 | 容器沿用 Docker；私有业务诊断已接现成应用缓存及经身份核验的 aria2 只读队列，不经过原厂 REST 启动／恢复包装。qB、Thunder 和通知任务仍须单独审计 |
| 相册、媒体、文件、分享、同步、云盘 | 私有业务诊断可采集媒体服务真实运行现场，任务进度仍保持未知；原厂 OCR、刮削及资源启动链存在副作用，未加入任务查询，不纳入普通硬件监控轮询 |
| 格式化、建阵列、改名、安装更新、自检 | 保留接口研究记录；本轮不接入控制，不试调用 |
| 通用 shell、原厂命令代理、任意文件或配置导出 | 不接入 Toolbox 网页或公共 API |

必须逐个 handler 审计副作用，不能根据 `get_` 前缀认定安全。例如：

- `get_smart_info` 的底层函数在本固件是未填充输出的 stub，不能作为可信 SMART 数据源。
- `get_self_test_status` 会运行没有 `-n standby` 的 `smartctl -a`，不能用于后台轮询或打开详情时查询。
- `get_fan_status` 会同步原厂温控信号，缺配置时还可能写默认值；沿用现有经过确认的控制流程。
- 应用中心某些“进度查询”可能更新配置，需与纯内存快照区分。

## 完整注册表及覆盖边界

应用、下载与媒体的固定私有诊断及实机验收见 [业务诊断](business-diagnostics.md)。应用缓存与 aria2 有界窗口可实际读取；媒体进度只保留尚未确认只读的状态，现场观察不作为任务数据。

- [emhistor 清单与分类](vendor-emhistor-interfaces.md)：33 个 IPC 命令、35 个顶层 REST 路由、29 张已关联动作表中的 902 个注册项；[JSON 原文](vendor-emhistor-interfaces.json)逐项保留处理函数与注册位置。
- [存储及独立服务清单](vendor-storage-interfaces.md)：152 条登记，包含存储服务 22 条命令及其子分支、摄像机服务 54 条命令和其他本地 socket／HTTP／消息服务的证据、风险与接入建议；[JSON 原文](vendor-storage-interfaces.json)。

这里的“完整”指明确列出的静态注册表枚举。6 个旧 REST 路由的内联分支、动态插件、未提供的云端服务及其他版本不在完整性声明中。未逐项确认的 handler 记为未知，不能当成已审核的只读接口。原厂会把公共库静态链接进多个进程，重复的 socket 字符串不能证明每个进程都提供该服务。

本轮读取固件、配置和已有缓存，不执行厂商二进制，不扫描或调用未知实机接口，不改原厂文件、磁盘私有元数据、风扇或灯效参数。
