# R1 灯光、温度联动与夜间亮度

Toolbox 按原厂固件的识别方式自动找到灯控，不再需要手选 I2C 总线。默认启动只读识别，不修改灯光；用户保存并应用已启用的灯光规则后，宿主服务才开始管理。部署容器退出不影响宿主服务中的联动和时间计划。

## 已确认的固件接口

证据来自用户已有的 `R1_X01_GML_STD_V6.3.3_Build_260907.zip`，分析日期 2026-10-28。仅静态读取脚本、ELF、字符串与反汇编，未执行原厂程序、扫描设备、加载模块或操作真实 I2C。

原厂 `emhistor` 的 SHA256 为 `402964bb23e32786db2a8d8b8a0ef2a2121cf6f753b4238cf5da53a4aa1c8d26`。其 `get_atmo_light_sumbus` 位于虚拟地址 `0xaeb4e2`，使用下面的内嵌字符串：

```text
0xdd1f58: i2cdetect -l | grep DesignWare | awk '{print $1}' | awk -F'-' '{print $2}'
0xdd1fc0: i2cget -y -f %d 0x26 0x01 | grep 0x55
0xdd1eb0: i2cset -f -y %d 0x%x 0x%x 0x%x
0xdd1f3d: i2cget -f -y %d 0x%x 0x%x
```

这证明总线编号是运行时枚举 DesignWare 适配器得到的，不能从固件写死为 `i2c-0` 或其他固定数字。`i2cdetect -l` 只枚举适配器；本实现改为读取 sysfs，不运行地址扫描，也不复制原厂的 `-f` 强制访问。

| 地址／寄存器 | 作用 | 静态证据 |
|---|---|---|
| I2C `0x26`，寄存器 `0x01` | 身份响应 `0x55` | 检测函数 `0xaeb4e2`，格式化命令 `0xaeb5e0` |
| `0x90` | 灯效模式 `0/1/2/3` | 设置 `0xaea8dd`；读取 `0xaeb731` |
| `0x91` | 独立亮度 `0–255` | 设置 `0xaed497`，读取 `0xaed6ae` |
| `0x92/0x93/0x94` | R/G/B，各 `0–255` | 设置 `0xaead99`，读取 `0xaeb23d` |

模式 `0` 为关闭，`1/2/3` 对应界面中的常亮／循环／呼吸选项。颜色分量与亮度分开写，不用缩放 R/G/B 冒充亮度。寄存器读回只证明设备接受了该值，具体灯效和肉眼亮度仍待实机观察。

原厂亮度函数对百分比乘约 `2.55` 后截断，getter 则向上取整。Toolbox 将百分比四舍五入映射到 `0–255`，读取显示使用最接近的百分比；恢复使用原始字节，不通过百分比来回换算。

原厂检测存在一个不能照抄的失败分支：逐个身份验证都失败时，末尾 `0xaeb684–0xaeb6cf` 仍可能返回最后的候选编号。Toolbox 必须取得真实、唯一的身份响应；有适配器不等于找到了灯控。

## 自动识别与写入边界

1. 只枚举 `/sys/class/i2c-dev/i2c-N` 与 `/sys/bus/i2c/devices/i2c-N`，要求名称包含 `DesignWare`、解析路径仍在 sysfs 内、对应 `/dev/i2c-N` 为实际字符设备。
2. 候选最多八个，只向已知地址 `0x26` 读取已知身份寄存器 `0x01`，不探测其他地址。
3. 必须恰好一个候选回应 `0x55`；再读取模式、亮度、R/G/B。模式只能为 `0–3`，所有读取必须返回合法字节。
4. 写入前重新验证身份与完整状态；只写发生变化的寄存器，模式最后写入，之后逐项读回核对。失败撤销旧能力，不用 `-f`、不加载驱动、不改原厂主题或服务文件。

固件的 `modules.builtin` 第 281、284–286 行包含 `i2c-dev`、DesignWare core/platform/pci，说明这套内核将相关驱动编入内核。它们与风扇所用 `hikio` 是不同接口：风扇 GNU Build-ID 不能替代灯控身份校验，缺少独立 `.ko` 文件也不代表 I2C 不可用。

没有设备、候选不唯一、总线已被内核占用而非强制读取失败或遇到未知模式时，保持不可用。默认只做一次自动只读识别；失败不进入后台反复探测。用户明确重新探测或应用时才再核验。

RGB 操作使用独立的操作锁，慢 I2C 命令不持有状态锁。状态读取和异步应用 ACK 不等待硬件事务；繁忙时旧即时 RGB 请求直接拒绝，不排队执行过期请求。

## 配置与运行语义

`LightPolicyController` 使用以下完整配置：

```json
{
  "schema_version": 1,
  "enabled": false,
  "mode": "temperature",
  "sources": ["稳定温度来源ID"],
  "stops": [
    {"temperature": 35, "color": "#00C832"},
    {"temperature": 60, "color": "#FFAA00"},
    {"temperature": 80, "color": "#FF3030"}
  ],
  "brightness": 70,
  "manual": {"mode": 1, "color": "#00C832", "brightness": 70},
  "schedule": {"enabled": false, "start": "22:00", "end": "07:00", "brightness": 15}
}
```

动作是 `light.policy.update`，参数为 `{"config": 完整配置, "apply": true或false}`。来源最多 32 个，颜色节点 2–8 个且温度递增，亮度范围 `0–100`。`rgb.probe` 使用空参数自动识别；不接收用户总线编号。

- **仅保存**：写入数据卷的 `light-policy.json`，保留当前运行的规则及开机恢复意图，不执行 I2C。草案中的 `enabled=true` 本身不会开启重启后的接管。
- **保存**：网页只有一个保存按钮，点击并确认后先完成文件与目录的持久化，再异步核验设备并应用。首次 HTTP 回应的 `settings_saved=true/pending=true/applied=false` 不表示硬件已经完成。
- **已应用**：后台取得寄存器读回，成功保存活动规则后，`active=true`；当前草案与该活动规则一致且不繁忙时，快照 `applied=true`。
- **开机恢复**：只恢复曾成功应用且显式启用的活动配置。未应用草案不会替换该配置。
- **停用联动**：先持久停用开机恢复，再释放灯光。设备故障或检测到外部改灯时也停用恢复，要求用户重新应用。

配置保存在独立的 `r1-toolbox-data` 数据卷，不保存在 Cookie、浏览器存储或部署容器可写层。文件采用原子替换、文件和目录 fsync；保存失败不会以“内存值相同”假报已保存。若数据卷本身无法写入，停用意图也可能无法持久化，错误会明确保留。

旧 `rgb.set` 仍属于即时操作，不自动保存为开机配置；联动占用灯光时拒绝该动作，防止两种入口争写。

## 温度与时间计划

温度模式从所选来源中取最高有效温度，在线性颜色节点间插值，超出端点使用端点颜色。使用实际单调采样时间：CPU/sysfs 来源有效期通常三秒；SMART 使用约三十秒慢采样，九十秒过期，不新增唤醒硬盘的探测。`0°C` 和合理负温度都是真实值。

来源缺失、无效、过期，或所选硬盘均处于已确认的休眠时，显示原因并切换低亮琥珀警示色，亮度不高于 `20%` 或用户设定值。不会用缺测值 `0` 或其他新鲜来源悄悄掩盖缺失项。该灯光提示不代替独立风扇的 CPU 过热保护。

夜间时间按 NAS 本地时钟解释，支持跨午夜，例如 `22:30–06:30`。计划内亮度是上限，不会把更低的手动／警示亮度调高；离开计划后恢复当前模式的正常亮度。每秒重新计算目标，仅当目标寄存器发生变化时写 I2C；相同目标不反复写入。

## 释放与原厂主题的关系

接管前在 RAM 中记录完整寄存器和适配器身份。正常停用或停止宿主服务时，仅在实际状态仍等于最后一次自写读回时，恢复接管前的原始字节。原厂 App、主题或其他程序已经改灯则保留外部状态，不把旧快照覆盖回去。

每次目标变化前会核对外部状态；目标不变时约三十秒进行一次只读核验。发现外部改灯后让回并停止联动，不靠持续抢写保持灯色。多个独立 I2C 命令不是跨进程原子事务，仍可能与原厂操作短暂交错；读回不一致会报告未确认，不能声称没有竞争。

正常停止可尝试恢复。进程被强杀、断电或内核 I/O 卡死不能保证立即恢复旧灯色，也未为灯光新增风扇式独立监督器；不得把正常退出恢复写成所有异常均已覆盖。重启后先重新识别，再按用户之前成功启用的规则恢复。

验证使用真实 Toolbox 控制器、真实 sysfs 温度目录、实际数据卷文件重建与 I2C 命令替身；硬件命令被替身接收，不接触 NAS。覆盖唯一设备、错误设备、只读识别、无强制访问、读回失败、所有权、原始字节恢复、外部改灯、最高温、零值、过期、跨午夜、持久化及慢 I2C 下快速状态读取。
