# 容量按需刷新

启动、两秒基本状态采样、任意 GET、被动检测和健康报告不测量挂载文件系统容量，也不通过 stat、realpath 或空间扫描补查用户挂载点。常规读取仅用有界 mountinfo／sysfs 内核元数据及合法内存快照。CPU／主板温度、风扇、磁盘身份与名称库存继续采样；磁盘 hwmon 温度和阈值停止读取。相关页面可显式请求补齐缺测，已启用的风扇硬盘温控另有受限温度需求；两者均见 [SMART 按需刷新](smart-refresh.md)。

物理盘大小仍来自内核 size，与文件系统的 total／used／usage 不同。冷启动或没有容量快照时，后者保持 null；不会拿物理大小推算剩余空间或从上次持久化结果补值。

## 所有者显式入口

`POST /api/r1/storage/capacity/refresh`，严格 JSON 空对象 `{}`。请求仍须同源、`Content-Type: application/json`、`X-FNM-Request: 1` 或现有配对 CSRF 证明；首次无网页登录口令沿用所有者开放模式，启用口令后需要有效会话。

Bearer Token、MCP、开发白名单及小屏令牌不授予此手动接口。拒绝查询参数／片段（包括空 `?`／`#`）、额外字段、磁盘／路径／命令／时限输入。固定目标仅由服务端内核枚举和身份校验决定；GET 不测量。

**这项手动刷新会读取文件系统元数据，可能唤盘。**它不具备 SMART `-n standby` 的跳过合同，也不会顺带运行 SMART。普通 SMART、强制 SMART 和手动容量刷新是不同操作。

## Web 进入刷新与缺测补齐

Web 进入存储页、磁盘详情或从 hidden 恢复该视图时，以所有者 `POST /api/r1/storage/refresh {}` 请求一次本次温度、状态和容量。即使已有合法容量快照，也仅对本批普通 SMART 独立确认非待机且同代的目标重新测量；既有成功缓存、refreshed 标签及 standby:null 均不能单独授权 statvfs。待机返回 `skipped_standby`／`standby`，电源不明返回 `unavailable`／`power_state_unverified`，保留仍合法的旧容量与原 sampled_at，不造新采样时间。换盘或挂载失效仍丢弃旧值。请求不接受 view、盘名、路径或 force，响应形状与下述 fill 相同；原手动容量接口不变。

Web 使用所有者 `POST /api/r1/storage/fill`；本机小屏使用独立令牌的 `POST /api/storage/fill`。两者严格接受 `{}`，不能传 force、盘名、路径或命令；Web 与小屏授权不互换。完整分段回执见 [SMART 按需刷新](smart-refresh.md)。

上述 fill 仅供概览和本机小屏相关页面在没有有效缓存时补齐，每个可见周期最多尝试一次；离页、网页隐藏或屏保后不再发新请求。服务器无页面租约采集器，轮询 GET 不触发补齐。fill 的容量已有合法快照返回 `cached` 并保留原采样时间。缺测只对本轮普通 SMART 已确认非待机且身份仍一致的目标测量；待机返回 `skipped_standby`／`standby`，无法确认则 `unavailable`／`power_state_unverified`。这些判断是附加拒绝门，不替代原挂载和设备复核，也不保证采样后磁盘仍维持同一电源状态。

同代失败短暂复用负结果，防止多个页面反复制造测量；可见周期结束或刷新失败不启用后台重试。风扇的条件性温度采集绝不触发容量测量。

## 固定批次回执

正常完成 HTTP200：

```json
{
  "ok": true,
  "status": "complete",
  "started_at": 1793430420.1,
  "finished_at": 1793430420.3,
  "results": [
    {"mount_id": 123, "status": "refreshed", "reason": null, "sampled_at": 1793430420.2}
  ]
}
```

`ok` 只表示批次已处理，逐行结果才表示该挂载是否取得测量；有失败或不可用时 `status:partial`。每行 mount_id 唯一，只是本次内核标签，不是调用者可传回的授权凭据。响应不包含真实路径、序列号、原厂原文或异常消息。

| 每行 status | 含义 |
| --- | --- |
| `refreshed` | 本次测量已通过授权及挂载／设备身份复核并进入内存缓存 |
| `failed` | 有界测量失败或超时，不能当成容量为零 |
| `unavailable` | 文件系统／设备身份不支持或无法确认，未使用替代扫描 |
| `identity_changed` | 采集前后或提交时来源变化，丢弃该结果 |

并发批次非阻塞拒绝 HTTP409、`{ok:false,reason:"busy"}`，不排队重试。无有效所有者授权 HTTP403，参数错误 HTTP400；其它不能完成的服务错误保留固定安全原因，不返回 stderr 或路径。

## 身份、时限与缓存

仅明确支持、能绑定真实物理设备的 `/drives` 块文件系统可测量，FUSE、未知、来源冲突和身份不明拒绝。内核挂载表按实际 EOF 有界读取；截断、歧义或不完整不能构成完整身份。身份包含挂载 ID、major/minor、target／root／文件系统以及 sysfs 设备生命周期，不能只按路径或 sdX 名称复用。

每批共用十二秒绝对单调窗口。测量在有界子进程中逐级 no-follow 打开固定挂载，核真实文件描述符的 mount ID／设备及前后身份后读取文件系统容量；父进程／被动轮询不打开或 stat 用户挂载点。超时不发布未完成结果；仍未退出的工作进程保持 busy，防止反复堆积。最多一个回收线程仅等待该子进程退出并关闭 IPC，不做磁盘探测，不必等下一次刷新才回收。不能保证杀死内核不可中断状态中的调用，也不宣传底层文件系统调用可原子取消。

缓存只在本次进程内保存，不落盘、不在启动自动初始化，也不长期持有用户文件系统句柄来 pin 挂载。真实测量句柄只在采集／提交期间短暂使用。缓存通过固定 `/proc/self/mountinfo` 的内核变更通知、命名空间身份及有界 proc/sys 复核保守失效；任意挂载事件都会清正／负缓存并更新共享代次，其他线程已观察到的变化也使旧在途结果不能复活。通知不可用、失效或无法证明覆盖时拒绝旧值，不用轮询前后恰好相同的 mount ID 冒充连续生命周期。换盘、同名复用、卸载／重挂、挂载 root／fs 变化以及不确定来源都不能给新来源套用旧值。

所有者代次与撤权锁存贯通采集、提交及 HTTP JSON 序列化前后，第一次失效后即使复权也不恢复旧响应；服务停止／重启不复活旧请求。每次提交和缓存投影均重验来源，缓存不是后续测量或文件访问的授权证明。

## 读取合同

原有 total／used／usage 字段继续表示实际取得的文件系统测量；未采集或失效为 null，0 仅用于真实零值。基本挂载容量行和网页物理盘行增加：

- `capacity_sampled_at`：原始 Unix 测量时间，未知为 null；周期采样和 GET 不更新它。
- `capacity_source`：固定 `manual_statvfs_cache` 是旧兼容标识，表示受限 statvfs 内存快照，也包括前台按需补齐；不承担手动／自动或当前已测量的语义。
- `capacity_status`：unknown／cached／identity_changed／unavailable；物理盘汇总多个分区只部分可用时可为 partial，并保留最旧的有效采样时间。

容量缓存没有套用 SMART 三十秒有效期；只要身份仍成立就作为有日期的历史快照展示，不能冒充实时余量或用来替代真实文件写入的空间预检。SMART 温度／健康仍独立三十秒到期；前台和已启用的风扇需求可以按受限规则补齐，但不能延长旧样本鲜度。

基本状态采样心跳缺失或过期时，CPU、内存等即时字段仍为未知；容量则继续经过同一被动挂载／设备复核投影，保留合法历史快照和原采样时间，不因基本心跳超过默认六秒门而被空状态隐藏。此路径不运行 SMART、容量工作进程或 statvfs，也不创建新的挂载监听。真实挂载事件、命名空间／设备变化、扫描不完整或监听丢失仍清除旧快照及在途批次，停止服务后不复活缓存。

本地生产链回归已确认旧实现的基本心跳过期会隐藏仍有效的容量；这不等于已确定 NAS 的唯一失效原因。`52da7` 实机保存帧只能证明刷新后先有容量、后续首次缺测时 SMART 仍有效，未保存基本心跳、容量代次及挂载事件原因；不能由挂载数量相同推断挂载身份未变。

移除后台温度和容量读取是去除潜在访问源，不证明这些调用曾唤盘，也不证明新版本已物理休眠。部署后仍需在不受主动刷新／媒体操作影响的完整原厂空闲窗口内另行验收；本轮实现与本机隔离测试不代替 NAS 结果。

## Linux 验证边界

`tests/test_capacity_refresh_mount_linux.py` 必须在 CI 的独立 UID0 步骤实跑五项且零 skip：临时私有挂载命名空间、只读 ext4、真实 Popen／JSON／SCM／fstatvfs 链、普通卸载成功、事件失效及超时／撤权／关闭后的回收。测试仅用临时 loop 文件系统并替换硬件身份映射，生产仍拒绝 loop；故障测试的受控 sleep 不代表实测不可中断内核状态。Windows 和普通用户发现套件的跳过不算这五项已通过。
