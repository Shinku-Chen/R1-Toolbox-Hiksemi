# MCP 文件的 Users 总边界

文件授权的最外层范围固定为 `/drives/*/Users/`。其中 `*` 恰好是一个已核验直接数据盘挂载的名称，大小写固定为 `Users`；这不是允许递归通配或由调用者传入的任意路径。

例如，已确认的数据盘挂载为 `/drives/space_1` 时，只能规划 `/drives/space_1/Users`。不能选择整个 `/drives/space_1`、应用目录、`users`、`Users2`，也不能把 `/drives/a/b` 当作另一个盘根。Token 可在该 Users 根之下进一步选择相对目录、只读或读写权限；角色、功能域、精确工具和文件范围仍须共同满足。

## 根规划与已有授权

`runtime/api_file_roots.py` 读取当前进程的内核 `mountinfo` 和已有磁盘身份投影。内部使用 `overview(include_identity=True)`，其身份来源 `storage_identity_cached()` 复用已有 SMART 与原厂匹配缓存，并通过受限 sysfs／udev 元数据重新核验设备生命周期；它不是完全不读文件的纯内存接口。默认 overview 仍隐去序列号，不能拿该脱敏值生成有效根。

上述路径不遍历数据盘，不 `stat` 或打开 `Users`，不读取用户文件或块设备，不查询原厂空间接口，不发起 SMART，也不通过规划结果声称目录存在或文件可读。完整序列号仅在内部参与摘要，不进入根目录输出或机器能力响应。

根 ID 保持 `root_<24hex>` 格式，但身份摘要改为 Users 专用的 v2 边界，并绑定物理序列号、分区设备、主次设备号、文件系统和具体 Users 路径。改磁盘标签不换 ID；换盘、换分区或换挂载路径使旧绑定失效。重启产生的新 mount ID 不改变资源授权，实际执行仍须重新核验打开对象。

旧整盘 ID 不会按磁盘名称改绑，也不会被静默缩小为新的 Users ID。旧 Token 仍可按原有管理流程编辑名称、来源 IP、开关等元数据；旧文件根只会显示绑定不可用。所有者必须显式选择新的 Users 根，才可保存新的文件范围。新根规划本身仍不授予文件 I/O 能力。

所有者 API 可查看规划的 Users 路径。机器能力与 `list_file_roots` 只投影当前 Token 已选根 ID、标签、相对目录及绑定状态，不返回宿主绝对挂载路径、序列号或未选择的盘。

## 不确定挂载的处理

以下情况不生成可选根：

- 没有唯一缓存身份，或同一序列号对应多个设备。
- 不是已支持的直接物理盘及文件系统，例如未核验的 RAID、mapper、虚拟盘或子目录 bind。
- 盘根被叠挂，或同一分区来源／主次设备号出现多个完整文件系统根挂载，无法唯一选择规范盘根。
- `Users` 本身或其任意子树存在额外挂载，包括虚拟挂载、只读挂载或 bind；不能把它们包含在上层根授权内。
- 内核挂载信息缺失、格式无效、超过长度上限，或当前数据盘挂载与缓存不一致。

`Users2` 或其他盘内兄弟目录上的独立挂载不扩展 Users 授权。只读属性分别核验挂载和超级块选项；只读变更不修改原授权，但会拒绝新的读写授权，并使已有写绑定不可用。

海康同一物理盘可同时存在两个独立分区的 `/drives/<名称>` 挂载。只要各分区来源与主次设备号唯一，并与该盘缓存挂载列表一致，就分别生成 Users 规划根；不能只按 `sda` 等物理盘名去重后把所有分区排除。完整根的重复挂载仍判为含糊别名。`/home/openclaw` 等 Users 边界之外的子目录 bind 不增加可选根，也不使原有唯一完整盘根失效；一旦 bind 目标落入某 Users 根本身或其子树，该根仍整体不可用。

所有相对路径使用未经 URL 解码的 POSIX 字面量。空路径表示所选 Users 根，非空路径不能有绝对路径、反斜杠、空组件、`.`、`..`、控制字符或无效 Unicode；上限为 1024 个 Unicode 字符及 4096 个 UTF-8 字节。`%2e%2e` 若作为字面文件名，不得在后续层再次解码成 `..`。这些词法检查不能代替符号链接与打开句柄的实际核验。

## 文件工具仍须补齐的证据

本次边界收紧并未把尚未接入的文件浏览、下载、上传和变更操作注册成可调用工具。`GET /api/access/file-readiness` 保持 `metadata_only`，只报告已有根规划和以下未闭合证据：

1. 当前运行固件的固定文件协议：HTTP 方法、编码、分页、虚拟路径到具体 Users 对象的映射，不能只凭离线固件动作名称推断。
2. Token 委托的 NAS 主体，以及该主体到可信 `uid`、`gid` 和附加组的映射；管理员已有会话不能自动充当所有 Token 的文件主体。
3. 原厂共享、虚拟权限或 ACL 与最终打开对象的有效权限关系，包含允许、拒绝及继承语义。
4. 同次操作中盘、分区、挂载、父目录和目标对象的实时身份；规划缓存不能证明 `Users` 不是符号链接，也不能证明它仍属原挂载。
5. ACL 判断与实际打开句柄为同一对象的证明，以及禁止越根、跟随符号链接、跨挂载和检查后换对象的安全打开机制；不能使用宿主 root 读取作为回退。
6. 下载正文、完整 Range 响应、有界传输、对象变动与断流后的验证语义。
7. 使用真实后端的只读实机验收，包括已知目录、权限拒绝和可比对样本字节。

上述条件未满足时，界面和能力目录如实标记待接入，不返回假成功的空目录。写操作还需验证目标父目录的实际写权限、原子提交、覆盖前置条件、幂等及可审计恢复，不能凭只读验收开放。

## 回归验证

```bash
python -B -m unittest discover -s tests -p test_api_file_roots.py -v
python -B -m unittest discover -s tests -p test_api_file_readiness.py -v
```

测试只创建临时的 `mountinfo` 样本并使用内存磁盘缓存，覆盖旧 ID 失效、精确 Users 边界、越界路径、只读、换盘、重复盘、别名、嵌套挂载、四盘各双分区与 SSD 外部子目录 bind，以及不泄露机器路径；不会读取 NAS 用户文件或改变磁盘休眠状态。
