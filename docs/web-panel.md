# 网页面板（fnMonitor 框架）

网页入口默认 `http://NAS_IP:18732`。面板直接使用
[fnMonitor](https://github.com/MisiteQ/fnmonitor) 的前端框架（MIT，固定提交
`d002d1d2e898222e989786ba607dad9810dcdb9a`，版本 2.19.0），源码在
`ui/panel-src/`，由 `python scripts/build-panel.py` 生成 `ui/web/index.html` 与
`ui/web/login.html`。本仓库不重写上游的模块、磁贴、导航、抽屉和设置控件；R1 专有内容
以新增模块和设置分组的形式加入。

网页是容器常驻核心，容器应持续运行；不再在部署后自行停止。小屏默认开启，可在“服务与开发”关闭并恢复官方窗口，网页监控、风扇和灯光服务继续运行。没有图形环境时也可启动 Web；停止整套容器时进入窗口与硬件恢复流程。

## 面板结构

网页顶部与手机底部导航统一为六个标签：**概览／存储／网络／应用／温度／设置**。

- **概览**：健康结论、时钟、核心指标（CPU／内存／存储／网络／温度）、趋势、
  算力与内存、进程、主机信息，以及 R1 新增的 **小屏与电源** 磁贴。
- **存储**：存储池用量与每块物理 HDD／SSD／NVMe；原厂当前空间列表通过两个固定只读 getter 取得，结合已有 SMART 缓存严格核对序列号、盘名和端口。海康名称无法确认时沿用 udev 文件系统卷标和 `/drives` 目录名，不能把回退卷标当成自定义名称。所有者进入存储页、磁盘详情或恢复显示该视图时，以固定 `POST /api/r1/storage/refresh {}` 普通刷新一次温度、状态和具有本批非待机证据的容量；休眠或电源不明跳过容量，保留历史快照原日期。概览仍只补缺测，轮询 GET 不探盘；强制 SMART 仅由所有者另行明确确认，不自动升级。SMART 不可用或三十秒过期时当前测量保持未知，盘位详情沿用同一抽屉。设备昵称与主机名分别显示，名称与测点同步；实机验证见 [存储名称](disk-names.md)。
- **网络**：网口速率、流量统计与容器流量。
- **应用**：容器列表、资源占用、端口与确认式启停；端口占用查询；内置应用在 R1 上为空。
- **温度**：温度测点、风扇与电压，R1 新增的 **双路风扇**、**机身灯光**，以及能耗。

存储盘位与顶部可独立显示所有者的“最近实测快照”，以原日期、历史状态和已测子集范围说明过去测量；当前挂载连续性不明时保持当前容量未知，不能把历史百分比写回当前池汇总。历史顶部只汇总同一已发布批次，待机兄弟的更旧日期不会混成新批完整池；换盘、身份未知、库存不全或冲突则不展示。该数据只来自已经完成的受控刷新，不为显示它新增 SMART、容量测量、轮询或文件访问。字段与授权／传输边界见 [容量按需刷新](capacity-refresh.md#当前容量与最近实测快照)，永久真实 HTTP 浏览器检查使用 `node tests/check_capacity_observation.cjs`。

首页与存储页另设“过去测量档案”区域，披露最近一个最终成功批次的过去数字。区域明确显示“当前归属未确认”“已测 N 个文件系统／M 块盘（子集）”“重启清空”和原完整日期区间；当时未用量为 `total-used`，不是 `f_bavail` 或现在可写空间。档案不与当前盘位、物理盘或池自动关联，不进入当前池汇总；当前未知仍显示 `--`。库存不完整、换盘、分区／parent／alias／namespace 变化后可保留该档案，但原盘位“最近实测快照”和同批汇总仍按完整库存与身份门永久删除，恢复同名身份也不复活旧盘位历史。

独立档案仅来自真实新测量且原所有者 JSON 前后、响应写入和最后发布守卫全部通过的一批，只含该批成功子集并按可信同设备去重；不混旧批或物理盘大小。全部失败、cached-only、空候选、回滚、迟到旧批及 JSON／写入／最后守卫失败不更新也不续日期。它仅在真实 password／pair／open 所有者的现有 `GET /api/overview` 顶层以 `capacity_observation_archive` 对象或 `null` 提供，无 per-disk archive、新接口或额外采集；公开 v1、MCP、本机小屏、Bearer、开发白名单及无 monitor／legacy 来源不扩展。对象通过正常 snapshot 同次私有 sideband 取得，最多沿用原每批 128 个候选测量，只存一个最新批次于 RAM，无 TTL、不持久化，start／close／重启清空。档案不授当前容量、空间预检、文件根、Token 或控制资格，字段合同见 [独立的过去测量档案](capacity-refresh.md#独立的过去测量档案)。本地 fixture 不证明 NAS 长期留存或物理休眠通过，也未追回旧八项实机拒绝的确切扫描谓词。

实时 CPU／主板读数与曲线使用同一份 Monitoring 温度缓存。主板曲线 `temp_mb` 对应实际 `board_temperature_c`，没有明确主板测点时显示未知，不能把 CPU 封装热区或 ACPI 的读数当作主板温度。原独立测点仍可查看，展示分类不改变风扇温控来源。

`overview.temp` 保留 `cpu`、`system`、`disks`，其中 `system` 与兼容别名 `mb` 都表示已证主板温度；`samples.cpu`／`samples.board` 提供真实 `sampled_at`、`sampled_monotonic`、`max_age_seconds`、`fresh` 和固定缺测 `reason`。有 Monitoring 但明确缺测时，不回退旧 basic／device 值；GET 不把请求时刻当新测量。旧嵌入没有 Monitoring 时，只接受确有原时间且三秒内的兼容缓存。

独立传感器列表同样使用 Monitoring 的 `temperature.*` 实际缓存及原测点名称，避免慢速设备库存过期后把仍有新测量的点显示为空。日期按首次合法单调到 wall 锚保存，同一个缓存样本重复发布或系统时间跳变不会刷新测量日期；缺测、未来与时钟回退仍显示未知。
- **设置**：双路风扇、机身灯光、小屏与显示、历史与告警、提醒阈值、天气、外观、登录口令、服务与开发、API 管理、连接与数据卷、关于。天气使用 Open-Meteo；空白位置按公网 IP 自动定位，也可填写城市或纬度、经度。外观、阈值与统计项即时保存；风扇点击“保存”即应用，不弹二次确认；灯光保存仍需确认。

布局可拖动排序、开关隐藏，外观（明暗、主色、字号、点阵数字、动效）与提醒阈值保存在
NAS 的 `panel-ui.json`，换设备或清缓存后自动恢复。

“小屏与显示”的屏幕保护内容支持混选 CPU／内存使用率、CPU／主板温度和具体温度测点，至少一项、最多十二项，点击勾选即保存。已选设备暂不可用时保留原选择并注明原因；不自动替换测点。小屏按保存顺序每页最多四项，超过四项自动轮换。屏保时限、亮度与关闭屏幕时间独立，详见 [屏幕保护](screen-saver.md)。

风扇均提供自动／高／中／低／手动：CPU 高／中／低使用独立固定输出 100／75／50%，
系统高／中／低使用原厂档位；手动直接显示温控曲线。保存立即应用，不需要先复位；
同一组已接管通道调整档位或曲线时直接更新目标，过热、缺测和必要的原厂交接仍保留。
系统原厂档位可以与 CPU 独立控制并存；页面单独显示实际原厂档位，切换中的请求不视为
已生效。旧固定值不自动取整或转换为原厂档位。选择自动并保存即可恢复该路原厂管理，
不再提供单独恢复按钮。完整切换、保护和兼容规则见 [风扇设置](fan-policy.md)。

## 数据来源

面板按 fnMonitor 的 HTTP 契约请求数据，`runtime/fnm_compat.py` 用 Toolbox 已有快照填充：

| 面板接口 | R1 数据来源 |
|---|---|
| `/api/overview`、`/api/system`、`/api/sensors`、`/api/fans` | 指标采样、设备库存、hwmon／thermal、显式刷新后的新鲜 SMART 缓存 |
| `/api/docker`、`/api/ports`、`/api/processes` | 应用、容器与端口采集 |
| `/api/history`、`/api/export`、`/api/report` | 本地 SQLite 历史与报告 |
| `/api/traffic`、`/api/power`、`/api/power_stats` | 计数器差值、RAPL 实测（不估算整机功耗） |
| `/api/hardware`、`/api/gpu`、`/api/disk_health`、`/api/smart` | 设备库存、显式刷新后的新鲜 SMART 缓存；`/api/smart` 仅投影缓存允许属性，不额外探测 |
| `/api/weather` | Open-Meteo 当前天气；自动定位或用户设置的城市／坐标，不经过 fnOS 天气服务 |
| `/api/r1` 及 `/api/r1/*` | 双路风扇、灯光、屏幕、电源、统计、登录口令 |
| `/api/services` 及固定 `/api/services/*` | 所有者管理小屏／MCP 开关和持久化开发窗口，不向 API Token 开放 |
| `/api/access` 及固定 `/api/access/keys/*` | 所有者管理独立 Token、角色、功能、文件范围、来源规则与审计 |

启动、后台库存、打开页面或详情均不执行 `smartctl`，也不为补字段扫 I²C 或写硬件。
SMART 温度与健康只读合法且三十秒内的缓存，过期或缺失为 `null`／`--`。
所有者显式 `POST /api/r1/storage/smart/refresh` 严格接受布尔 `force`；默认待机保护、
单次强制可能唤盘，均不授予机器 Token 或开发白名单。固定回执与边界见 [SMART 按需刷新](smart-refresh.md)。

fnOS 专有集成（应用中心、iDRAC、阵列卡、巡检自检、面板自更新、外部通知）
在 R1 上返回明确的“不可用”，不生成占位数据，也不显示对应设置分组。

## 鉴权

默认首次没有网页登录口令，监控与管理直接可用；设置并开启口令后需要会话。显式选择 `pair` 模式才要求旧五位配对流程。设备写入始终保留同源／JSON／CSRF、参数与能力校验，风扇和电源等沿用各自确认及保护。

### 登录口令模式（宿主默认）

宿主部署默认只使用登录口令，不再要求配对。需要兼容旧配对流程时可在 Compose 设置：

```yaml
R1_WEB_AUTH_MODE: "pair"
```

默认口令模式下，登录口令默认未设置，网页写操作直接可用；启用口令后，写操作需要先登录。配对码卡片在小屏网页设置页隐藏。**未设置口令时，任何能访问 18732 的设备都能修改设置，请只在可信局域网使用。**

### 配对模式（仅兼容旧部署）

1. **五位配对码**（兼容模式）：在小屏“控制中心 → 网页设置”生成，180 秒有效、一次使用；
   网页在需要授权时弹出输入框。配对会话最长 8 小时，服务重启后失效。
2. **登录口令**（可选）：在“设置 → 登录口令”设置，至少 6 位；只保存 PBKDF2-HMAC-SHA256
   哈希（`panel-auth.json`，0600），会话只存 sid 的 SHA-256（`panel-sessions.json`），
   有效期 1–30 天。开启后访问面板需先登录，写入也由该会话授权。

未解锁时 `/api/r1` 仍返回风扇/灯光当前规则、温度来源与屏幕设置，用于展示现状；它不包含口令哈希、会话或配对码，所有写入都在服务端重新鉴权。

登录口令保护的是面板页面、面板接口与所有写操作；`/api/v1/*` 仍是公开只读接口（与启用口令前一致，详见[公开API](public-api.md)）。需要连监控也保密时，请在网络层限制 18732 端口。

外观、主色、字号、布局与提醒阈值的保存只影响面板显示，不需要配对；它们同样走同源 `POST + X-FNM-Request`，但不会改动设备。

写请求同时要求同源 `POST`、`Content-Type: application/json` 和 `X-FNM-Request: 1`
（或配对会话的 `X-R1-CSRF`）；登录失败有按来源与全局的双层限速。面板不保存配对码，
不通过网页生成配对码，也不把会话材料写进只读 API。

忘记口令：在 NAS 上删除数据卷中的 `panel-auth.json` 后重启服务，即可恢复为未设置口令；
已有风扇／灯光／历史配置不受影响。

## 服务开关与 API 管理

“设置 → 服务与开发”分别控制小屏、MCP 和开发模式。小屏开关是保存意图，实际是否完成需看 `active/busy/last_error`；界面只在窗口内短期核对切换状态，不用勾选成功代替真实接管。关闭小屏恢复官方显示，Web 继续运行；Web 是必需核心，常驻模式不提供关闭端口 `0`。

MCP 默认关闭，启用后客户端仍须使用独立 Token。API 管理提供只读／读写／管理员角色、十五个显式功能域、文件根与相对子目录、来源 IP／CIDR 和有效期，并支持编辑、停用／启用、一次性 Token 轮换、不可逆撤销。轮换立即使旧 Token 失效，编辑默认保持原到期时间与原权限；旧键不会自动升级。文件传输、Docker 部署等尚未实现的域清楚标为“待接入”，授权规划不代表工具已可用，见[MCP 与 API 管理](mcp-api.md)。密钥列表只在主动打开和操作后获取，不参与十秒监控轮询。

## 开发者免配对模式

局域网 AI 常规接入使用“API 管理”的独立 MCP／REST Token，不依赖本节开发窗口。网页所有者授权与机器 Token 分开，开发白名单不能创建或管理 Token；完整用法见[MCP 与 API 管理](mcp-api.md)。

原厂媒体的按需测试使用 `POST /api/dev/media`，固定请求为 `{"action":"probe"}`（相册识别）或 `{"action":"probe_all"}`（七类媒体状态）；播放清晰度诊断使用 `{"action":"probe_transcode","path":"/drives/<disk>/Users/admin/...","confirm":true}`。诊断只显式发送三个固定 getter；原厂可能读取媒体、写 `user.md5` 并唤盘，不显式发起播放、停止或设置写入。宿主复用已有管理员会话，凭据与原始路径不出宿主，保持有效开发白名单与媒体锁，不纳入被动快照。服务端观测、电视端静态推导与实际播放分别标记。详细范围见[媒体验证](media-probe.md)。

需要白名单 IP 直接检测时，使用统一 `POST /api/dev/diagnostics`：在开发模式有效窗口内可免登录查询目录或采集设备、存储、业务与风扇只读现场，不需要命令开关。它和上述媒体按需测试是本节口令要求的明确例外，原有诊断和控制接口保持原授权；同源、JSON、CSRF 校验继续生效。请求示例与返回语义见[开发者白名单检测](dev-diagnostics.md)。

网页“应用 → 原厂业务状态”使用 `GET /api/business` 读取应用快照、独立 aria2／qB 队列及上次媒体结果。所有者可通过固定 `POST /api/r1/business/refresh` 显式采集应用或媒体，后台轮询不重发签名查询。原 `POST /api/dev/business` 仍只接受 `{"action":"snapshot"}` 并保留开发者、口令与同源要求；不提供原厂 REST 任意转发。各来源及实机边界见 [业务状态](business-diagnostics.md)。

开发模式默认关闭，推荐通过“服务与开发”开启；必须填写非空局域网 IP／CIDR 白名单和有效时长。Web 保存的绝对到期时间写入原数据卷，重启不续期；窗口有效后，每个请求还需命中实际来源。仍保留同源、`X-FNM-Request`、确认和操作锁，不改变小屏令牌或 MCP 权限。下列环境变量仅兼容尚无持久服务设置时的初始化：

```yaml
environment:
  R1_DEV_NO_PAIRING: "1"
  R1_DEV_ALLOW_IPS: "192.168.31.193"
  R1_DEV_MINUTES: "60"
  R1_DEV_ALLOW_COMMANDS: "1"   # 可选：只读诊断命令
```

- 尚无持久设置时 `R1_DEV_NO_PAIRING=1` 与非空白名单才启用；默认关闭。保存后的 Web 设置优先于环境。
- `R1_DEV_ALLOW_IPS` 支持精确 IP、局域网 CIDR 与 IPv4 点分掩码，逗号分隔；不接受域名、通配符、空名单或覆盖公网的网段，始终使用真实连接来源。
- 环境初始化窗口从本次启动计算，默认 60 分钟、最多 1440 分钟；仅未保存的兼容初始化可能随重启重新计算。Web 保存后使用绝对到期时间，不自动续期。
- 如果已设置面板登录口令，原有控制和诊断接口仍要求先登录口令；固定 `/api/dev/diagnostics` 和明确发起的 `/api/dev/media` 接受开发者白名单直接检测。
- 调试结束可直接在 Web 关闭开发模式，无需为开关窗口反复改 Compose 或重打镜像。请求示例及过期规则见[开发者白名单检测](dev-diagnostics.md)。

原有固定命令接口还需要启用 `R1_DEV_ALLOW_COMMANDS=1`（统一检测入口不依赖此开关）：

```http
POST /api/dev/exec
Content-Type: application/json
X-FNM-Request: 1

{"name": "blocks"}
```

命令名固定为 `identity`、`uname`、`processes`、`blocks`、`failed_units`、`fan_units`、`boot_log`、`fan_files`、`fan_status`、`fan_process`。接口不接受 `cmd`、`shell` 或参数拼接，不能用它执行任意命令；输出截断到 64 KiB、10 秒超时。需要更多诊断命令时必须修改白名单代码。日志可能包含主机信息，只在调试窗口内使用。

## 风扇接管调试接口

风扇排障使用 `POST /api/dev/fan`，通过同一个接口读取现场、限时采集和查询结果；需要重试时，先启动采集，再复用正常接管流程。不要反复增加少量错误字段、打包、要求用户换镜像猜原因。

该接口要求上一节的开发开关、实际来源命中 IP／CIDR 白名单、有效窗口和受限命令开关全部满足（环境初始化名为 `R1_DEV_ALLOW_COMMANDS=1`）。已设置且启用登录口令时，还必须携带正常登录会话；口令会话不能替代开发开关。所有操作都要求同源 `POST`、JSON 和 `X-FNM-Request: 1`（或有效配对会话的 CSRF 头）。诊断不放进公开监控 API，不接受任意命令、文件路径、环境变量或上传代码。

四种请求体：

```json
{"action":"snapshot"}
{"action":"capture","duration_seconds":45,"interval_ms":250}
{"action":"result","id":"上一次返回的任务 id"}
{"action":"retry","confirmed":true,"duration_seconds":45,"interval_ms":250}
```

- `snapshot`：返回完整只读现场，包括服务版本、固件与驱动预检、字符设备、原厂配置、PID／启动时间／可执行文件、信号掩码、guard 映射、监督状态和真实就绪判定日志。缺失字段保持 `null` 并注明读取失败或截断；不调用有副作用的 `get_fan_status`，不读取 SMART。
- `capture`：只采集，不保存或应用配置。返回 HTTP `202` 和 `job.id`，通过 `result` 查询；默认采集 45 秒、间隔 250 毫秒。首个样本包含完整预检，后续只记录变化，不重复计算二进制哈希。时长限制为 1～60 秒，间隔限制为 100～2000 毫秒，最多 600 个样本；采集数据预算为 4 MiB，其中最终现场最多 1 MiB，截断会明确标注。
- `result`：返回该任务的采集状态和样本。`completed` 只表示采集结束；接管是否成功必须看实际策略的 `active`、`last_error` 和恢复状态。只保留最新一个任务，重启服务后内存结果消失；旧任务或错误 id 返回 `404`。
- `retry`：必须明确传入 `confirmed:true`，且已保存配置至少有一路为 `manual` 或 `temperature`。先采集原始状态，再调用现有 `fan.policy.update` 应用已保存配置；接口不接收新配置，不自动选择档位。仍执行全部硬件身份与唯一进程预检、租约、就绪检查和失败恢复。HTTP `202` 表示已发起，后续通过 `result` 读取异步结果；采集启动失败时不会重试接管。

同一时间只运行一个采集任务，重复启动返回 `409`；接管正在切换时，可以采集，但不能重复重试。后台采集只读取有界文件，不获取适配器的长时间控制锁，不启动常驻轮询。停止容器／Web 核心会停止采集。

监督进程把真实的就绪判定写入对应 RAM 目录的 `readiness.json`，保留首个、最近和失败事件及有界时间线；恢复原厂时继续追加，不覆盖之前的失败。字段包含判定时的信号掩码、进程身份、guard 路径与匹配结果、读取字节数、稳定窗口和剩余等待时间，避免从被截断的异常字符串猜原因。诊断文件写入失败不改变控制或恢复流程。接口只返回白名单诊断字段，不暴露原厂环境变量值、恢复描述符或租约内容。

例如，在已登录的 NAS 面板开发者控制台中发起一次带采集的重试：

```js
const request = body => fetch('/api/dev/fan', {
  method: 'POST',
  headers: {'Content-Type': 'application/json', 'X-FNM-Request': '1'},
  body: JSON.stringify(body)
}).then(response => response.json());
const started = await request({action: 'retry', confirmed: true});
console.log(started);
// 稍后重复查询同一任务；不要重复发起 retry。
console.log(await request({action: 'result', id: started.job.id}));
```

实机验收：先用 `snapshot` 核对版本与预检，单独 `capture` 确认不改变原厂管理；再按用户授权 `retry`，查询同一任务到采集结束，对照监督端判定和完整 `/proc` 快照定位失败。开发机上的 fixture 测试不会访问 NAS 或修改真实风扇；真实接管效果仍需部署后通过此接口验证。

## 已知边界

- 网页不展示 CPU 功耗／显卡／能耗卡片；原始 RAPL 读数仍保留在 API；上游按 RAPL + 底座/硬盘估算整机功耗，R1 不估算，
  因此构建时把相关文案改为“CPU 封装实测（非整机）”。
- 盘位与存储池的对应关系来自宿主 `/proc/self/mountinfo`（`/dev/sdX*` → `/drives/...`）。
  挂载关系与容量采样分别判断：已有挂载但没有合法容量快照时显示“容量未采集”，关系未知时保持未知，不用缺测数值证明未挂载。使用 LVM／多路径等未以 `/dev/sdX` 暴露的数据盘时，物理盘关联可能不完整；存储池仍仅汇总已核验文件系统的有效快照并去重，部分覆盖不代表全部硬盘的总体使用率。
- 单盘休眠、容量缺测或刷新失败不隐藏其他盘的合法容量；同代历史快照保留原值与原日期。健康灯同时核对当前 SMART 的新鲜度，过期或缺测不沿用独立巡检缓存中的旧正常等级；温度缺失本身不等于健康失败。最近观测显示真实 SMART 采样时间，不将网页轮询时间当成新的检测时间，也不为改善显示自动唤盘补采。
- CPU 分核、进程、端口、GPU、IPv6/DNS 等只显示本机真实可读字段；缺失为 `--`，
  不使用估算或占位。
- 开机以来的流量累计没有独立计数器时不显示；今日/本月来自真实计数器差值。

## 与 fnMonitor 的差异

API 管理支持只读／读写／管理员角色、逐功能授权和文件范围，默认只读，角色提升不会自动勾选其他功能。现有密钥显示原有精确权限；文件、Docker 部署、应用、下载、影视、相册等新业务明确标记待接入，仅可保存预授权。能力自查和参数见 [MCP 与 API 管理](mcp-api.md)，实施顺序见 [AI 功能接入路线](ai-capability-roadmap.md)。

- 品牌文字与“飞牛 / fnOS”提示改为 R1 Toolbox；渲染逻辑与样式未改写。
- fnOS 专有的设置分组（服务端口、打开方式、功耗估算参数、通知、iDRAC、巡检、
  自更新）不显示；R1 用双路风扇、灯光、小屏、登录口令、连接分组替代。
- 新增 `/api/r1` 运行时与 `/api/r1/*` 写接口；所有写操作仍走原有的能力检查、
  确认流程与硬件身份验证，不新增任意命令。

## 本地演示

不需要 NAS 也能调试网页与小屏：

```sh
python scripts/build-panel.py
python tools/demo/run.py --host 0.0.0.0
```

网页面板 `http://电脑IP:18732/`，小屏 `http://电脑IP:18731/`。两者共享同一份内存假 NAS：小屏生成的配对码可解锁网页；网页的风扇档位/曲线/温度设备、灯光策略会同步到小屏只读状态；小屏亮度/息屏也会反映到网页。演示不执行真实电源、不伪造 RPM、不访问宿主硬件，完整说明见 `tools/demo/README.md`。

## 部署与升级

面板文件随镜像交付，展开到宿主 RAM 目录；配置写入 `r1-toolbox-data` 数据卷。
升级或重建 Compose 时必须复用原项目与数据卷，不要删除卷或使用 `down -v`。
删除部署后正常重启可恢复官方显示。
