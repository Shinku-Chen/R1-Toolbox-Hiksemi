# 功能与支持条件

R1 Toolbox 已将参考项目和 r1-panel 安装包中的一部分需求独立实现。下表区分三种状态：**已实现**表示代码与界面已接入真实 API；**依宿主能力**表示功能已接入，但必须由宿主提供设备、命令和权限；**未提供**表示本版没有实现。自动化检查通过不等于硬件已在当前 NAS 验证。

## 功能对照

| 功能 | 状态 | 本版范围与限制 |
|---|---|---|
| 七页触屏 UI | 已实现 | 概览、存储、网络、控制、应用、系统、设置；点击导航、左右滑动、内容滚动 |
| 主题与字号 | 已实现 | 深空、晨光、水墨、青玉；字号 80–140% |
| 启用页面与轮播 | 已实现 | 可禁用页面，至少保留一页；轮播 0–3600 秒，0 为关闭；设置入口保留以便恢复 |
| 无操作息屏 | 已实现 | 0–86400 秒，0 为关闭；首次触摸仅唤醒，不继续触发按钮 |
| 夜间低亮度 | 已实现 | `HH:MM` 时段，支持跨零点；亮度 5–100% |
| 立即调亮度/息屏/唤醒 | 依宿主能力 | 要求可用的 backlight/blank 节点；退出时尽力恢复接管前的原始值 |
| CPU、内存、运行时长 | 已实现 | 真实 `/proc` 采样，CPU 首次差分显示采集中；含分核、负载、Swap |
| CPU 温度 | 依宿主能力 | 使用宿主可读传感器；缺测显示 `--` |
| 数据盘容量 | 已实现 | `/drives/` 下真实挂载点，按文件系统去重 |
| 物理磁盘与温度 | 依宿主能力 | sysfs 设备信息、hwmon 温度，或可用的 SMART 温度；休眠与不支持不伪造读数 |
| SMART 健康状态 | 依宿主能力 | `smartctl -n standby -j -a`，后台执行与 30 秒缓存；不会主动唤醒休眠盘，不启动自检 |
| 网络 | 已实现 | 默认路由接口、各接口 IPv4/MAC/状态及速率；逐接口展示，不把桥接流量简单相加 |
| 进程、监听端口 | 已实现 | 有界采集，包含可读的 TCP/UDP 监听信息；权限不足时显示缺失项 |
| GPU | 依宿主能力 | DRM/sysfs 设备信息；利用率、显存只有宿主存在对应字段时才可用 |
| CPU/内存趋势 | 已实现 | 服务内存中最近 120 次采样；UI 显示最近采样，不提供跨重启历史 |
| 风扇 RPM | 依宿主能力 | 显示 IT87 通道同号 `fanN_input`；有读数也不代表物理对应已经确认 |
| 风扇手动/档位/自动 | 依宿主能力 | 显式接管 IT87 hwmon 通道；手动 50–100%，档位 60/80/100%；温度缺测或停转读数回退满速 |
| 自定义风扇温控曲线 | 未提供 | 当前自动模式使用内置温度规则，不能编辑曲线 |
| RGB 颜色与灯效 | 依宿主能力 | 明确选 I²C 总线，非强制读取 `0x26` 验证后写颜色/模式；未完成当前 NAS 实机灯效验证 |
| RGB 亮度、温度联动 | 未提供 | 当前仅颜色和关闭/常亮/彩虹/呼吸模式 |
| Docker 列表与资源占用 | 依宿主能力 | 需要可用 Docker 命令与权限；缺资源统计时保留状态和原因 |
| Docker 启动/停止/重启 | 依宿主能力 | 每次界面确认；禁止对 Toolbox 保留容器操作；无创建、删除、镜像或 Compose 管理 |
| libvirt 虚拟机 | 依宿主能力 | `virsh` 列表与状态；确认后 start/shutdown/reboot/suspend/resume；无 destroy/删除 |
| NAS 重启/关机 | 依宿主能力 | 确认后有 5 秒可取消，使用 `systemctl`；不提供 RTC、WOL 或关机自开机 |
| 设置持久化 | 已实现 | 独立 Docker 命名卷 `/data` 中的 `settings.json`；缺卷时仅本次开机保留 |
| 远程 Web 写入管理 | 未提供 | API 仅监听本机回环地址，普通浏览器预览只读 |
| 每日固定亮熄屏/RGB 计划 | 未提供 | 夜间亮度和无操作息屏不等于固定开关计划 |
| 天气、SMTP、Server酱、iDRAC、月报 | 未提供 | 无占位卡片、外部凭据配置或后台发送 |
| fnOS 相册/影视/音乐统计 | 未提供 | 本版面向官方固件，不读取 fnOS 专有数据库 |
| 参考软件激活、试用或注册机 | 未提供 | 不包含参考包授权模块，不修改其激活机制 |

## 当前 NAS 的硬件支持

当前用户的官方内核为 `6.1.66-001`，已发现 `gpio-it87`，没有 IT87 hwmon/PWM 通道。**当前风扇调速不可用。** `gpio-it87` 提供 GPIO，不能替代风扇驱动。Toolbox 不自动加载内核模块，也不使用 `/dev/port` 绕过驱动访问硬件。

将来宿主提供受支持通道后，控制页才会出现接管操作。通道以实际 `hwmonN:pwmN` 标识，不硬编码“CPU 风扇”或“机箱风扇”；操作前仍需确认真实对应。同号 RPM 为零时提高至满速并报告原因，不能把此处理当作已解决接线、驱动或风扇故障。

RGB 的 I²C 工具和 `/dev/i2c-*` 存在只是前提。用户选择总线后，服务先读取地址 `0x26` 的模式寄存器，验证失败时不写入；不默认扫描所有设备，不强制访问被占用的地址。灯效效果仍需实机确认。

## 数据、控制与恢复

UI 和 Python 服务从经过校验的 `/run/r1-toolbox` RAM 包运行，前端只读绑定到官方 Electron 的私有文件视图。官方 AppImage、解包版前端和启动脚本不被覆盖；Docker 容器完成部署后会自行停止。

设置通过独立命名卷持久保存，停止容器和重启 NAS 不会删除它。采样历史、当前风扇接管、RGB 总线选择和待执行的电源请求不作为自动恢复配置保存。没有可用数据卷时，设置存入 `/run`，重启即清空。

本机读取 API 为 `GET /api/status`、`GET /api/toolbox`、`GET /api/insights`。写入统一通过 `POST /api/action`，需要本次启动随机生成的 `X-R1-Token`，并检查 Host/Origin。令牌仅注入小屏 Electron 环境，因此普通浏览器预览禁用写操作；不会将令牌放入前端文件或只读状态返回值。

正常退出服务时会取消未执行的电源请求，尽力恢复接管前的风扇 PWM/enable、屏幕亮度/blank 原始值。原始亮度为 0 也会按原值恢复，因为当前实机上 0 不一定表示画面已关闭。RGB 不自动恢复原灯效。突然断电、强制结束进程或节点消失时，恢复逻辑可能无法完成；这些情况需要实际状态检查。
