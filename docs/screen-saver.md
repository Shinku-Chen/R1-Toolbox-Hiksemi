# 屏幕保护显示项目

网页进入“设置 → 小屏与显示”，或在小屏“设置”中开启屏幕保护后，可勾选希望展示的项目。CPU／内存使用率、CPU／主板温度和后台已经发现的具体温度测点可以混选，例如 CPU 使用率、内存使用率和某块硬盘温度一起显示。

至少保留一项、最多十二项，按勾选顺序保存并即时生效。每页最多四项，超过一页每十秒自动轮换并显示页码；高度不足720px的预览窗口每页两项，保留字号与可读性。触摸、按键或其他原有唤醒操作仍会退出屏保；关闭屏幕优先于屏保。屏保时限、屏保亮度和关闭屏幕时限互相独立。

## 数据与异常

使用率来自已有监控快照，具体温度来自既有温度来源目录，页面不会运行新命令、触发风扇接管、发起额外 SMART 查询或唤醒硬盘。数值为0时保留0；缺测、来源失效、读数过期或连接中断时显示 `--`。明确的硬盘休眠状态标为“休眠”，不把旧温度当成当前温度。

每个项目独立核对依赖接口与实际采样时间：快速状态使用自身 `timestamp`，最多10秒；设备温度缓存使用 `device.sampled_at`，最多90秒，不用顶层快照时间替代。具体温度来源继续遵守目录给出的新鲜度、年龄和有效期，客户端只会增加样本年龄；其他接口正常或重新刷新页面都不能延长旧读数的有效期。CPU 温度与主板温度按明确来源区分，CPU 温度区、磁盘和显卡不会充当主板温度。

已选温度测点使用来源目录中的稳定 ID，设备断开时保留选择并显示不可用，不按照 `hwmon` 编号、`sdX` 顺序或另一个有效设备偷偷替换。温度恢复后显示恢复采集的值。长标签允许换行，界面保持小屏单列触摸布局。

## 设置协议与兼容

设置仍保存在原数据卷的 `settings.json`，写操作走现有 `settings.update` 授权、同源与 CSRF 校验，不另建开放写接口。新增 `saver_items` 字段，为1–12项不重复的字符串列表，列表顺序就是显示顺序。

| ID | 显示内容 |
|---|---|
| `cpu_usage` | CPU 使用率 |
| `memory_usage` | 内存使用率 |
| `cpu_temperature` | 原有 CPU 温度汇总 |
| `board_temperature` | 原有主板温度汇总 |
| `temperature:<source_id>` | 现有温度目录中的具体来源 |

`source_id` 保留原值，不按显示标签反查。后端只校验允许的格式、长度和数量，允许格式合法的离线来源继续保存；不能根据设备当时是否在线删除配置。温度测点名称按纯文本显示。

默认仍显示 CPU／内存使用率。旧设置只有 `saver_content: "temperature"` 时迁移为 CPU／主板温度，旧 `usage` 迁移为 CPU／内存使用率。旧客户端显式更新 `saver_content` 且没有提供新列表时继续映射相应两项；显式提供 `saver_items` 时以新列表为准。只改屏保时限、亮度或其他设置不会重置已经选择的项目。

新增设置、协议迁移、混选保存、页面重载、未知与休眠显示、分页轮换、窄屏布局和触摸唤醒通过隔离快照与浏览器检查覆盖。真实面板字形、背光效果及不同固件可提供的温度来源仍以 NAS 实机为准。
