# MCP 与 API 管理界面

网页“API 管理”卡片直接提供 MCP／REST 服务开关。首次读取服务状态时不读取 Token 列表；点击开关立即通过所有者授权的 `/api/services/mcp` 保存，不弹出操作确认。请求期间禁止重复点击，保存失败显示原因并读取一次真实状态；不自动重放写请求。关闭服务会保留已有 Token，客户端立即停止访问。

卡片提供三个独立入口，弹层内可直接切换页面：

- **添加 Token**：按只读、读写、管理员角色，选择功能、具体工具、文件范围、已登记 Docker 项目、独立未来部署资源、来源 IP／网段和有效期。提高角色等级不自动增加工具权限；新增工具默认不选。
- **Token 管理**：查看安全元数据，编辑授权、暂停／启用、轮换或撤销。轮换和撤销保留明确确认；权限修改不隐式延长有效期。撤销后不提供恢复入口。
- **Token 操作**：查看当前设备连接地址、动态工具能力目录、文件／Docker 接口定义与最近调用记录；通过独立的「部署资源管理」登记未来服务。此页不收集旧 Token，不用网页会话代理机器调用。接口定义和原生资源候选依然按需读取。

Token 明文仅在创建或轮换后的专用窗口显示一次。复制由用户明确点击；关闭或按 Escape 会清空 Token 及客户端配置字段，不写入浏览器存储。关闭后重新进入添加页使用只读角色与状态读取工具，不保留上次的表单草稿或明文密钥。

文件授权入口说明固定边界 `/drives/*/Users/admin/`，只展示后端核验的根目录；子目录以 admin 根为起点使用相对 POSIX 路径，不重复添加 admin/；旧 Users v2 范围需显式重选，不自动改写。多个范围取并集，下级只读不能收窄上级读写。界面不以角色代替具体工具或资源授权，不将尚未接入的写入、安装或文件能力宣传为可用。

Docker 项目逐项选择 `inspect`、`control`、`update_image`：读取可授只读角色；启停／重启和镜像更新要求管理员、具体工具及对应项目操作同时满足。新增操作默认不选，提高角色不自动追加，降级时清除超出等级的操作；更新的执行保护见[固定项目操作](docker-project-operations.md)。

未来部署资源使用独立 `deployment_*` 和 Token `docker_deployments` 字段，不能拿虚构项目代替。在「Token 操作 → 部署资源管理」显式查询可用具名卷和网络，填写固定仓库、非 root 用户、资源上限、可选卷及具体端口，再确认登记；此操作不拉镜像或创建容器。登记只保存在 Toolbox，撤销不停止服务或删除卷；「重新核验」用于所有者重核 NAS／daemon 重启后的同一资源和容器，使旧计划失效，不扩大 Token 权限。目录读取和登记失败保留真实原因，登记失败保留输入，不自动重放。

Token 对未来资源分别授予 `inspect/deploy/control/remove`，写操作仅管理员、默认不选。Docker 域可只选择现有项目或未来资源其中一类；无需虚构另一类。只修改名称、来源或有效期时省略未改动的资源字段，保留原授权；角色降级会明确清除写操作，提高角色不恢复。固定卷是独立委托，不将文件 Users 边界宣传为容器沙箱。部署、更新、删除的边界见[受控新服务部署](docker-deployments.md)。

界面按实际工具、角色、域和资源展示，文件／Docker 二十一合同逐项标记；应用新装额外选择审计 application_ids，新键默认空，旧键不因安装白名单扩大而扩权。Token 操作提供 owner 固定恢复区预检／初始化／撤销／检查／恢复，打开页面不扫描用户文件。

下载工具委托固定本机下载器的既有任务，不接收新目标路径、内容或任意选项；它们不等于给整个下载器建立 `/drives/*/Users/admin/` 沙箱。该 Users 边界仍是 Toolbox 文件接口的硬限制，不能据此宣称已约束原生引擎全部任务。

界面复用 fnMonitor 设置卡片、弹层、输入控件和按钮。三个页面不同时展开；手机使用单列入口、单列工具与 Token 元数据，长地址、范围和记录可换行，在 320px 宽度无需横向滚动。

验证：`node tests/check_api_management.cjs` 覆盖服务开关、三页隔离、Token 生命周期、逐工具和资源授权、应用对象初值／编辑保留／不注入 HTML，以及 owner 恢复区的显式预检／初始化／撤销／恢复与 `index_verified:false` 的准确显示，保留部署资源、秘密清理和 320px 检查。`node tests/check_service_settings.cjs` 继续核对设置同步。固定入口与实际权限条件见[file-mutations.md](file-mutations.md)。

真实 HTTP 权限／派发回归另见 `tests/test_mcp_business_operations_http.py`；原厂响应和下载连接使用固定 fixture。这些结果不表示新增功能已完成 NAS 实机验收。
