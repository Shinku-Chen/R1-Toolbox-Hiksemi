# 架构与运行时

本文归档 R1 Toolbox 的宿主运行方式、服务边界和恢复路径。部署步骤见 [部署与升级](deployment.md)，具体硬件与接口边界见对应专题文档。

## 组成

| 组件 | 运行位置 | 职责 |
| --- | --- | --- |
| `tools/boot-once/` | Docker 容器前台 | 展开 UI 包、启动宿主常驻服务、转发停止信号并监督生命周期 |
| `runtime/ui_service.py --resident` | 宿主命名空间 | 本机 API `127.0.0.1:18731`、Web 入口 `0.0.0.0:18732`、指标采集、容量／SMART、硬件控制 |
| 小屏管理 | 宿主 systemd 临时服务 | 只读绑定内置前端，启动原厂 Electron `AppRun`；关闭时恢复官方窗口 |
| Web 面板 | 浏览器 | fnMonitor 框架与 R1 扩展；网页配置、Token、设置与详情 |
| 数据卷 `r1_toolbox_data` | Docker 卷 | 面板设置、风扇／灯光、统计、服务开关、开发窗口、Token 摘要和显示缓存 |

Web 是常驻核心；小屏和 MCP 是独立可选服务。图形环境、Electron 或小屏故障不得阻止 Web 启动。

## 生命周期

1. 容器前台从镜像读取内置 UI 包，校验后展开到宿主 `/run/r1-toolbox`，并确认目标位于 tmpfs。
2. 前台以宿主命名空间运行 `ui_service.py --resident`，由单实例文件锁拒绝第二套核心。
3. 常驻服务启动本机 API、Web、监控、风扇／灯光和可选小屏管理。
4. 容器停止时依次停止接收请求、停止 Web、恢复小屏、恢复灯光和原厂风扇、停止采集并释放接口。
5. 删除部署后正常重启可恢复官方显示；恢复失败会保留真实原因，不把失败报成成功。

原厂 AppImage、已有解包目录、启动脚本和厂商服务保持原样；只有 `/screen` 已挂载且派生目录缺失时，Toolbox 才从原厂 AppImage 生成 `squashfs-root`。自动解包失败只影响小屏，不阻塞 Web。

## 端口与授权

| 入口 | 默认地址 | 授权 |
| --- | --- | --- |
| Web 面板 | `http://NAS_IP:18732` | 默认口令模式首次免口令；设置口令后需会话；同源／JSON／CSRF |
| 本机 API | `127.0.0.1:18731` | 本机小屏独立 `X-R1-Token`；不向网页或 MCP 复用 |
| MCP | `http://NAS_IP:18732/mcp` | 独立 API Token，默认关闭 |
| 公开 API | `http://NAS_IP:18732/api/v1/*` | 只读公开状态；不授予控制 |

`R1_WEB_BIND=127.0.0.1` 可限制 Web 只监听本机。Web 默认监听 IPv4；网络详情支持 IPv6 不代表 Web 已监听 IPv6。

## 数据与显示缓存

`/data`（或部署指定的数据卷）保存持久配置、统计数据库、Token 摘要和 `disk-cache.json`。显示缓存只保存最近成功观测的物理盘型号、物理大小、SMART 温度／健康可用性、休眠标记和固定 `/drives/*` 挂载容量；不保存序列号、命令输出、Token、请求数据或用户文件。

显示缓存用于重启和页面切换后立即展示，不参与容量资格、SMART 鲜度、风扇、文件空间预检或控制授权。页面进入存储页时仍尝试一次真实 SMART／容量采集；失败保留缓存展示。详见 [容量刷新](capacity-refresh.md#显示缓存)。

## 存储与 SMART

- 容量仅在显式刷新或页面进入补齐时测量，GET 不执行 `statvfs`、`stat` 或用户挂载访问。
- 当前容量绑定挂载 ID、设备身份、文件系统和设备生命周期；真实数据盘变化或扫描不完整时失效。
- 主机 mountinfo 中 Docker overlay 等无关事件不直接清空未变化容量；状态投影和前台批次重新核对实际数据盘行。
- SMART 使用待机保护的普通命令；休眠盘默认跳过，手动强制刷新可能唤盘并需确认。
- 页面不展示采样时间或缓存状态；未知读数保持未知。

详见 [容量刷新](capacity-refresh.md)、[SMART 按需刷新](smart-refresh.md) 和 [磁盘名称](disk-names.md)。

## 风扇与灯光

- 风扇控制分为 CPU 与系统通道；自动／原厂模式不启用独立接管，只有手动或固定档需要受监督的适配层。
- 接管前核验原厂温控二进制、唯一进程、字符设备和已加载驱动；退出、租约失效或故障时请求安全输出并恢复原厂执行者。
- 风扇输出百分比是请求值，不是实测 RPM；RPM 不能伪造。
- 灯光通过已识别的原厂 I²C 设备控制，支持关闭、常亮、彩虹、呼吸四种原生灯效。
- 手动风扇需要网页保存温度来源；小屏只提供快速档位。

详见 [独立风扇温控](fan-policy.md)、[灯光策略](light-policy.md) 和 [界面使用说明](interface-guide.md)。

## 文件、Docker 与 MCP

- 文件读取限定在匹配固件和原厂所有者身份的 `/drives/*/Users/admin/` 子树；写入有独立的 admin 信任锚、逐级 no-follow、真实挂载／FD 核验和恢复区合同。
- Docker 只开放固定列表、状态和启停；不提供任意 Compose、命令、`exec` 或镜像管理。
- MCP／REST 使用独立 Token；角色、功能域、文件范围、应用对象和来源共同授权；旧键不自动扩权。
- 开发者模式只开放固定只读诊断，不接受任意 Shell。

详见 [文件变更与恢复](file-mutations.md)、[Docker 部署](docker-deployments.md)、[MCP 与 API 管理](mcp-api.md) 和 [开发者白名单检测](dev-diagnostics.md)。

## 故障边界

- Web 端口必须可用；不可用时常驻服务报告启动失败，不用空循环伪装健康。
- 小屏、Electron、灯光或监控失败只影响对应能力，网页核心继续运行。
- 恢复原厂管理失败时保留原因和重试入口，不自动认为已恢复。
- 未知、过期、身份冲突和权限不足都显示未知或不可用，不填 0，不猜测。
